# 护栏的其余编辑路径：rename 被拒、archive 生效（打包版真机）

- 日期：2026-09-18
- 实例：**打包版** `dist/mac-arm64/PureScience.app`（1.64.0），独立端口 44103、独立 `--user-data-dir`、CDP 9334；`runtime/` 硬链
- 语料：真实数据根的副本（`/tmp/ps-bench-paths`，59 会话；真实根未被指向）
- 路径：**真实窗口 + 真实鼠标** —— 首页「最近的会话」行 → 工作区 → 会话操作菜单（`重命名…` / `归档`）→ 弹窗内真输入框 + `Rename` 按钮
- 目标会话（同一项目 `cmtyf335n0002wfoqwwuw25j3`）：B = `请为我获取人类新型假想蛋白序列…`（9 条消息）、C = `请执行"24 个月虚拟研发与 FDA 模拟审评"任务…`（33 条消息）

## 一、结果（一组"该拒的拒、该过的过"）

| 路径 | 该会话在 store 里的状态 | 文件实测 | 判定 |
|---|---|---|---|
| **Rename**（走 store saver） | **仅摘要**（从未打开） | 323,416 B → **323,416 B**；`mtimeMs` 未变；sha256 `2c56e0767907` → **`2c56e0767907`**；消息仍 9 条 | ✅ **保存被拒**（逐字节未变） |
| **Rename**（走 store saver） | **已读回文档** | 322,875 → 322,792 B；sha256 `3dbc2f4ce46a` → `112844a17ad2`；标题落盘为 `RENAMED-BY-PROBE-2`；**消息仍 9 条** | ✅ **写入生效且未截断** |
| **归档**（走 main 侧 `sessions:update-archive`，不经 saver） | **仅摘要** | 956,768 → 956,801 B；`archivedAt: 1789742201121`；**消息仍 33 条** | ✅ **如期生效且未截断** |

**读法**：拖走数据的分岔只有一条 —— "store 里只有摘要、却把它写回盘"。实测表明 **saver 那条路（rename）在摘要态被挡住**，而**主进程那条路（archive）本来就不读内存里的摘要对象、而是按会话身份在磁盘上打补丁**，所以它应当成功，也确实成功且没有截断。两者合起来覆盖了"编辑会话"这条链的两类实现。

## 二、判据对照

- 摘要会话的 saver 路径：**要么被拒（文件逐字节不变），要么写完整文档** ⇒ **被拒** ✅
- 非 saver 路径（main 侧命令）：**应当成功且不截断** ⇒ **成功，消息条数不变** ✅
- 结论：**没有出现静默截断**（既不是 pin 那条老缺陷的复发，也没有新增同类洞）。

## 三、诚实边界

1. 单次行为开关（每条路径各一次），不是统计量。
2. 覆盖面是**两条**编辑路径（rename / archive）＋ 先前那条 pin（`docs/evidence/2026-09-18-lazy-guard-live-verification.md`）；**没有**穷举菜单里的每一项（下载产物 / 导出会话 / 删除 等未驱动）。
3. 打包版 macOS arm64；dev 实例上的同两条未再跑（pin 那条已在 dev 与打包版两边都有）。
4. `C` 的归档是在 **B 已打开**的同一进程里做的 —— 即"同一进程里既有已读会话、也有摘要会话"的混合状态，这正是要验的场景，但也要说明：它不代表"只有摘要会话"的极端状态。

## 四、过程中的两个操作坑（已写进 skill）

1. **探针里的选择器不能用闭包**：`page.evaluate` 会把函数序列化过去，外层变量不会跟着走 ⇒ `ReferenceError: selector is not defined`。把"选择器 + 匹配模式 + 关键词"作为**数据**传进去、在页面内构造匹配逻辑。
2. **读日志/探端口要等文件写完**：应用还在启动时读日志只拿到一半（本轮 76 行 vs 实际 180 行），据此我一度把"启动正常"误判成"卡死"并立了案 —— 已收回。判据：**先确认进程已进入可服务状态（端口在听 / 窗口有可点元素），再读日志下结论**。
