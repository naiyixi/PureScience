# 中文查询归一化：政策按**来源自己的行为**决定（2026-10-10）

批次 ① 把中文归一化接进了 PubMed，并在那里定下「不可映射即**具名拒答、一个请求都不发**」。
本轮把同一张表接到 **OpenAlex**，而政策**必须不同** —— 依据是实测，不是习惯。

## 一、两个来源的实测行为（都是真读数）

| 来源                      | 中文查询                                                     | 英文（表里的 term of record）                                         |
| ------------------------- | ------------------------------------------------------------ | --------------------------------------------------------------------- |
| PubMed（批次 ①，curl）    | `term=阿司匹林` → **0**（`No items found.`）                 | `term=aspirin` → 44,xxx 级                                            |
| **OpenAlex**（本轮 curl） | `search=阿司匹林` → **11,867**；`search=高血压` → **47,119** | `search=aspirin` → **443,778**；`search=hypertension` → **3,065,850** |

PubMed 的理由成立（"中文查询必返 0，发了只能换来看起来像答案的 0"）；**同一句话在 OpenAlex 上不成立**
（它索引并回答中文）。所以：

- **PubMed 政策 = `refuse`**（默认）：`query` 只含已映射部分，`unmapped` 非空即具名拒答 —— 因为 `query`
  不能冒充"整个问题"的答案。
- **OpenAlex 政策 = `keep`**：认识的重写成 term of record（覆盖高得多），**不认识的原样搜**并在 `zh_terms.unmapped` **点名**。
  丢掉了反而是**拿掉一个能用的检索**。

政策在共享层是**显式选项**（`planChineseQuery(raw, { unmapped })`），不是两套实现：一张表、一个规划器、
两种**具名**选择。

## 二、经应用自己的连接器取得的读数（一次性探针，跑完即删）

| 请求               | 实际发出               | `api_total`   |
| ------------------ | ---------------------- | ------------- |
| 阿司匹林用于高血压 | `aspirin hypertension` | **131,360**   |
| 阿司匹林 机器学习  | `aspirin 机器学习`     | **22**        |
| 阿司匹林           | `aspirin`              | **443,778**   |
| 高血压             | `hypertension`         | **3,065,850** |

`zh_terms` 逐条回带了 `matched`（含 kind 与 english）、`removed`（虚词如 `用于`）、`unmapped`、`query_sent`。
第二行是关键：未映射的中文**留在请求里**，而且**确实拿到了 22 条** —— 政策的前提（这个来源答中文）由真读数支撑。

## 三、覆盖面的边界（如实说）

共享表的 217 词条是**医学向**（药名/适应证/机构名/期刊名/虚词）。因此 OpenAlex 上的中文查询里，
**非医学部分多数会落进 `unmapped`** —— 它们会被搜、会被点名，但不会被重写成英文（表里没有）。
扩大覆盖面 = 扩表，是**另一个单元**，不在本笔。

## 四、arXiv：本轮**未接**，原因是缺一条必须的读数（立案）

要接 arXiv 就要知道它对中文的行为（决定 `refuse` 还是 `keep`）。探它时
`export.arxiv.org` 连续回 **HTTP 429 `Rate exceeded.`**（间隔数分钟后仍是 429）⇒ **这条读数今天取不到**。
按仓规不替它编政策、也不把"没测"写成"不需要" —— 立案，等能取到读数再定。

**下一轮取它的一步**：`curl -s -o /tmp/a.xml -w '%{http_code}' 'https://export.arxiv.org/api/query?search_query=all:阿司匹林&max_results=0'`，
读 `totalResults`；非零 ⇒ 用 `keep`，为 0 ⇒ 用 `refuse`（与 PubMed 同政策），两种都照本档的写法落。

**另注（给下一轮的自己）**：`export.arxiv.org` 对**密集探测**敏感 —— 不要连着打；一次取一个读数。
