# 主色上的文字对比度实测（V9 / IC4 真机读数）

> 日期：2026-10-03。依据 `docs/plan-2026-10-03-v1.81.0-queue.md` 的 **V9**：
> 「按按钮实际字号/字重给出对比度数值；**不达标才**微调前景色」。
> 背景：v1.80.0 把主色对齐品牌蓝 `#4D6BFE`（`--primary: oklch(0.5915 0.2202 269.6)`，真机像素读数
> `rgb(77,107,254)`），但「白字压在它上面够不够」从未测过——这条就是补测。

## 0. 结论（实测数字）

| 量 | 真机读数 |
| --- | --- |
| `--primary` | `oklch(59.15% .2202 269.6)` → 画出来是 **`rgb(77, 107, 254)`** |
| `--primary-foreground` | `oklch(98.5% .005 264)` → 画出来是 **`rgb(248, 250, 254)`**（不是纯白） |
| 主按钮真实排版 | **16px / weight 400**（读数取自面板里的真实 CTA「Import」） |
| **对比度** | **4.144 : 1** |
| 判定 | 正文口径（<18.66px 粗 / <24px）门槛 **4.5** ⇒ **不达标** |
| 深色态（同法计算） | `oklch(0.74 0.137 269.6)` 上的 `oklch(0.25 0.04 266)` = **6.785 : 1** ⇒ 达标 |

**读法与代码一致**：spec 里把两个 token 各画到一个 1×1 canvas 上读像素（Chromium 把 `oklch()` 原样序列化，
只读 computed style 只能证明 token 文本），再按 WCAG 的相对亮度公式算
`(Lmax+0.05)/(Lmin+0.05)`。离线用同一公式独立复算，得到 **4.144**，与真机逐位一致。

## 1. 关键发现：排期里预设的修法**够不着**

排期写的是「不达标才微调前景色」。但**前景色已经是天花板**：

| 前景（压在 `rgb(77,107,254)` 上） | 对比度 |
| --- | --- |
| 当前 token `rgb(248,250,254)` | 4.144 |
| 纯白 `rgb(255,255,255)`（理论上限） | **4.330** |

⇒ 把前景调到纯白也只到 4.330，**仍然低于 4.5**。这条修法本身无法达标，必须换一条：
**加深承载文字的主色**（背景越暗、白字对比越高）。

同色相（269.6）同彩度（0.2202）下，达到 4.5 所需的最小加深与几个可用档位：

| `--primary` | 画出来 | 对比度 | |
| --- | --- | --- | --- |
| 现值 `oklch(0.5915 …)` | `rgb(77,107,254)` | 4.144 | ✗ |
| 临界 `oklch(0.5718 …)` | `rgb(72,100,247)` | 4.525 | ✅ 刚好 |
| **建议 `oklch(0.56 …)`** | **`rgb(69,97,243)`** | **4.721** | ✅ 留出余量 |
| `oklch(0.53 …)` | `rgb(62,87,232)` | 5.383 | ✅ 更稳 |

## 2. 为什么不直接改（**拍板项**）

品牌蓝 `#4D6BFE` 是**用户明确拍过两次**的产品决定（"主色=DeepSeek 蓝 `#4D6BFE`，仅主 CTA 渐变"）。
把它从 `rgb(77,107,254)` 改到 `rgb(69,97,243)` 只差 8/10/11 个色阶、肉眼几乎不可分，
但**它是品牌决定，不是我能替用户拍的**。所以本片只把数字与选项摆出来，**不动代码**。

两条路（择一，一行即可拍）：

- **(A) 加深主色**：`--primary` 改 `oklch(0.56 0.2202 269.6)`（浅色态）；深色态已达标不动。
  ⇒ 一键达标，代价是品牌蓝整体略深一点点。若要保持「渐变里的蓝」完全一致，可只给**承载文字的
  主色面**另立一个 token（如 `--primary-strong`），渐变/描边继续用 `#4D6BFE`。
- **(B) 接受并记录**：主 CTA 上的白字对比度 4.144 低于 AA 正文线，作为已知可访问性欠账落档，
  不改配色。这不影响功能，但**不许**再说「主色已对齐且无遗留」。

## 3. 真机读数怎么取的（可复跑）

```bash
npm run build:e2e   # 改过 renderer ⇒ 必须重建
npx playwright test e2e/certification/journal-metrics-panel.spec.ts --workers=1 -g "names year and source"
```

读数原文（[panel-reading] 前缀）：
```
--primary token: oklch(59.15% .2202 269.6) → paints as: rgb(77, 107, 254)
--primary-foreground token: oklch(98.5% .005 264) → paints as: rgb(248, 250, 254)
primary-text contrast: 4.144:1
primary CTA typography: {"fontSizePx":16,"fontWeight":400,"label":"Import"}
primary-text verdict: 4.144:1 falls short of the 4.5 floor (body text at 16px/400)
```

守卫（写死在 spec 里）：`expect(contrast).toBeGreaterThanOrEqual(3)` —— **只设下限不冻结现值**：
比值升高是好事，掉到大号文本线 3.0 以下才算回归。

## 4. 明确没做 / 已知边界

- **未改任何配色**：见 §2，品牌色是拍板项。
- **只测了一个 CTA**（面板里的「Import」，16px/400）。按钮组还有 `text-sm`(14px/500)、`xs`(12px)、
  `sm`(12.8px) 等尺寸，全都属"正文"口径，因此换一个按钮只会让门槛相同、不会改变结论；
  各自的字号未逐个取读数。
- **未测 hover / disabled / 渐变**：`hover:bg-primary/80` 会改变背景（进而改变对比度），
  以及主 CTA 渐变上的文字，都**未取读数**，本条不声称覆盖。
