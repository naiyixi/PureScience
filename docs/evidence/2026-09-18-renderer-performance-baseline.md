# 渲染层性能基线（真机窗口 + CDP 采样）

- 日期：2026-09-18
- 实例：`electron-vite dev` **带窗口**实例，**真实数据根**（`~/PureScience-DEV` + `~/.purescience-project`，60 会话）
- 采样方式：Electron `--remote-debugging-port=9333` + Playwright `connectOverCDP`（脚本在 `/tmp/renderer_perf.mjs`，**刻意不放进仓库**：放进仓库会触发 electron-vite 重建，应用重启、CDP 瞬断 —— 这一点踩过一次）
- 原始读数：`/tmp/renderer_perf.json`

## 一、数字

| 指标 | 读数 | 口径 |
|---|---|---|
| 空闲帧间隔（中位） | **16.7 ms** | `requestAnimationFrame` 采样，即稳定 60 fps |
| 空闲最差帧 | 124.4 ms | 1 帧 > 50 ms（1798 帧样本） |
| 空闲长任务（>50 ms） | **0** | `PerformanceObserver { entryTypes: ['longtask'] }` |
| 页面重载 → DOMContentLoaded | 1232 ms | `page.reload` 计时 |
| **搜索面板打开** | **578 ms** | 点入口 → 面板 DOM 出现（DOM 正则匹配，非猜文案） |
| 视图切换 | 803 ms | 其中 **800 ms 是我脚本里写死的等待**，不是应用耗时 —— 这个数**不能当结论** |
| **交互期间长任务** | **4 个 / 最大 524 ms / 合计 742 ms** | 覆盖"开搜索面板 + 切视图"两段 |
| **交互期间最差帧** | **548.4 ms** | 40 帧样本中 5 帧 > 50 ms |

## 二、结论（可支撑的部分）

1. **空闲时渲染层不卡**：60 fps、零长任务。所以"卡"不是持续性的渲染开销。
2. **一交互就出现半秒级冻结**：最大长任务 524 ms、最差帧 548 ms —— 与用户"目前卡、不如对标产品流畅"的主观反馈**方向一致、量级吻合**。

## 三、诚实的负面结果（未证的部分）

1. **"可见可交互"时刻没量到**：我用来判定的文案正则（`New project` / `新建项目`）没匹配上 ⇒ `interactive = -1`。**只有 DOMContentLoaded 的 1232 ms 是可信的**，它**不等于**用户看到内容的时刻。
2. **524 ms 冻结未归因**：采样窗口同时覆盖"开搜索面板"和"切视图"两段，**没有分开**。归因需要分两轮各采一次。
3. **视图切换的 803 ms 无效**：800 ms 是脚本的固定等待。
4. `longtask` 是 Chromium 的粗粒度信号，**不等于**"用户在等"的时长；它只说明主线程被占住了。

## 五、采样流程本身的两次坑（写进流程，而不是靠记性）

1. **窗口可能加载到"不是本次 dev server"的端口**：日志里 vite 在 `5174`，窗口却加载 `5173` ⇒ 页面**空白**（实测 `buttons:0 textLen:0`）—— 那一轮的读数**全部作废**（本档第一节的数字取自 **UI 确实挂载**的那一轮：脚本用 DOM 正则点到了搜索入口、面板也真的出现了，否则会返回 -1）。
2. **Electron 的 CDP 参数会被 electron-vite 的自动重启丢掉**：重启后的 Electron 进程上**没有** `--remote-debugging-port`。

**因此采样流程改为"不满足校验就中止"**：① `ps` 确认 CDP 参数在**活着的** Electron 进程上；② 窗口 URL 的端口必须等于日志里 vite 的真实端口；③ DOM 必须挂载（可点元素 > 0）。该流程已按设计**中止过一次**（`CDP flag on live process: MISSING` → `ABORT`），而不是再产出一组无意义的数字。

## 六、下一步

1. **归因那 524 ms**：把"开搜索面板"和"切视图"分成两次采样，各自读长任务与帧间隔；
2. **再判是否命中 hydration**：护栏要的是"可见可交互"时刻，用应用自己的 aria-label / i18n key 取（`HomePage.tsx` 的 `home.searchSessionsAndArtifacts` 那类），而不是猜文案；
3. 这两步做完再决定两级目录的**目标数字**：现在的 55 MB / 1.3 s 服务端 + 传输，是否就是这 524 ms 的主因 —— 若不是，先治真正的主因。
