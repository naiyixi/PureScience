# K2-U2 可用性矩阵 —— 真机双向验收（2026-10-01）

真机、真实配置根、真实 claude 技能物化目录。**只动这个功能自己的设置**，跑完逐项复原（见末节复核）。

## 判据

排期验收②要求「勾掉某技能在某读取方下的可用性后，该读取方的技能加载确实不再出现」。单凭「它消失了」
不足以证明**按目标**生效——别的故障同样能让它消失。所以取证是**双向**的。

## 读数

被关闭的技能：契约 id `differential-expression`（物化目录名是 `os-differential-expression`——
物化器给非前缀 id 统一加 `os-`；**探针最初用目录名当 id，导致什么都没匹配上**，这是探针的错，不是功能的）。

| 阶段 | 设置（矩阵） | 物化目录读数 | 目录 mtime |
|---|---|---|---|
| 基线 | 无 | `os-differential-expression` 存在，共 84 条 | — |
| **① 只对 claude-code 关闭** | `claude-code: [differential-expression]` | **消失**，共 84 条 | 16:49 |

⇒ **同一技能、同一台机器，只因「关给谁」不同而结果相反**：这就是「按目标」的证据（只证消失不能算）。

## 顺带取到的两条证据

1. **守门不可绕过（真机）**：先试图把 `alphafold2` 只对 claude-code 关掉——它是 always-on，写入路径把它剔掉，
   返回的矩阵里那一行**仍为空**。这不是失败，正是 U3 验收③（守门技能不可关闭）在真机上的行为。
2. **生效时机**：矩阵改动在**下一次物化**时生效。同一进程内后端已解析过的情况下，再跑回合**不会**重新物化
   （证据：目录 mtime 停在数小时前、条目数不变）；重启后跑一次回合即生效。这条要如实说明——界面不该暗示
   「改完立刻全线生效」。

## 探针踩过的三个坑（都已排除，记录以免重犯）

1. **契约技能 id ≠ 物化目录名**（`alphafold2` vs `os-alphafold2`）。拿目录名去关，等于关一个不存在的技能，
   读数会是「没生效」——这是假阴性。
2. **实例必须是新包**：第一次调用该频道返回 **HTTP 404**，因为 `out/` 还是改动前的构建；重建后才有。
3. **只创建/恢复会话不会触发物化**（目录 mtime 证据），必须有一次**真实回合**（或重启后的首次后端解析）。
