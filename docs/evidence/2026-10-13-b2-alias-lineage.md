# B2 第一片：别名级跨运行血缘（判定引擎 + 界面具名原因 + 可复算配方）

> 范围：v2.1.0（批 B）第 2 件 **B2「别名级依赖血缘」的第一片**。执行器单元（2026-10-13 夜）。
> 本片交付**判定与呈现**那一半；**内容哈希落进运行记录**那一半具名未做（见第五节）。

## 一 缺口是什么（先写红线，再动手）

既有标记 `computeStaleRunIds`（`src/shared/run-dependencies.ts`）只看**名字**：某次运行写过的变量名，
被后面某次**已完成**运行再写一次 ⇒ 那次运行判「已过期」。它看不见两种「一个名字都没被改、
但值已经变了」的情形：

| #   | 形状                 | 例子（同一会话、按顺序）                                                  | 旧规则                                                               |
| --- | -------------------- | ------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 1   | **原地变异**         | r1: `df = load()` ／ r2: `df['stage'] = 'qc'`                             | 看不见（r2 的名字表里没有 `df`）                                     |
| 2   | **经别名的原地变异** | r1: `df = load()` ／ r2: `frame = df` ／ r3: `frame.dropna(inplace=True)` | 看不见（`frame` 与 `df` 不是同一个名字，且 r3 没有任何赋值到基础名） |

第 2 种是「别名级血缘」要回答的那一半：**值被改了，但没有任何一个被记录的名字被写**。判据
（本片交付）：一次运行被标「已过期」时，能指名**是哪一次运行、通过哪个名字（别名链）、改在哪一行**，
且这些字段**只靠 run.json 就能复算**。

## 二 交付（提交与本片文件）

| -------- | --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| 呈现单点 | `src/renderer/src/lib/notebook-stale-copy.ts`（新） | 三种原因各一句；呈现只留这一份，主进程只给数据（与 `notebook-risk-copy.ts` 同一约定）                                                                                                                                             |
| 界面     | `NotebookPreview.tsx` 的 run 行                     | 既有「已过期」徽标**不改**；旁边多一条 `data-testid="notebook-cell-stale-reason"`，并把判定依据逐项挂在元素上（`data-recipe/variable/via/alias-chain/later-run/mutation-kind/line/content-hash`），`title` 给出真正被改的那行代码 |
| 字典     | `notebookStale.*` **3 键 × 9 语**                   | zh 值不等于 en 值；九语均无未填占位符（有门禁用例）                                                                                                                                                                               |

**规则表**（每条具名，可读可指认）：

| 规则                                                                 | 判定                                                                                                                                                                                                               | 说明                                                         |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------ |
| `alias-binding`                                                      | 整行形如 `name = name2`（或 `name <- name2`）                                                                                                                                                                      | 两个名字指同一个对象                                         |
| `inplace-call`                                                       | `name.method(...)`，method ∈ {append, extend, insert, remove, pop, clear, sort, reverse, update, add, discard, difference_update, intersection_update, symmetric_difference_update, setdefault, popitem}           | 这些方法**默认就改自己的对象**                               |
| `inplace-call`（opt-in 族）                                          | `name.method(...)` 且同行出现 `inplace=True`，method ∈ {drop, dropna, fillna, rename, sort_values, sort_index, reset_index, set_index, replace, astype, clip, interpolate, drop_duplicates, set_axis, rename_axis} | **没有 `inplace=True` 就不算**（`df.dropna()` 是返回新对象） |
| `subscript-write` / `subscript-augmented-write` / `subscript-delete` | `name[...] = …`、`name[...] += …`、`del name[...]`                                                                                                                                                                 | 改的是名字背后的对象                                         |
| 原因 `name-rewrite`                                                  | 后面某次已完成运行**重写了这个名字**                                                                                                                                                                               | 与旧规则同解，只是现在**指名**是哪一次                       |
| 原因 `direct-mutation`                                               | 后面某次已完成运行在**同名的对象**上原地改动                                                                                                                                                                       | 别名链为空                                                   |
| 原因 `alias-mutation`                                                | 同上，但那次运行用的名字是本会话里 `name` 的**别名**                                                                                                                                                               | 带上别名链（如 `frame` 或 `frame>view`）                     |

**不猜的边界**（都有用例钉住）：`b = a.copy()` **不是**别名（改 `b` 不算改 `a`）；三引号字符串块内、
注释内的行不参与判定；别名**只在它下面**的行生效（同一次运行里写在绑定之前的使用按绑定之前的意义解）；
某个名字被重新绑定后，指向它的别名一并作废（否则会把后面的改动算到错的运行头上）；别名链在跨运行
**按顺序**解，且每次运行只报**最早**那一次改动（同一次里「重写名字」优先于「改对象」——重写是读者本来
就会想到的那一种解释）。

## 四 可复算配方

```
stale reason = producing run id + sha256(utf8 cell source) + variable + alias chain
             + mutation point (later run id, 1-based line, matched line text, mutation kind)
             under rule set notebook-alias-lineage:v1
```

- **独立复算用例**（测试自己写一遍，不调被测模块的助手）：测试用 `node:crypto` 自己算 `sha256(script)`，
  与行里带的 `producerContentHash` 逐字符比对；并逐字段清点行里**只有** run.json 能给出的那几项。
- **缺失 ≠ 通过**：拿不到哈希的运行（早于收据写入侧）记 `'not-recorded'`，**不**在本模块里就地算一个
  ——摘要只在主进程算（`src/shared/**` 同时被 node/web 两个 tsconfig 编译，共享层不得 import `node:crypto`），
  第二处算哈希就是第二个配方。界面那句**不**声称哈希，哈希作为可核对的属性挂在元素上。
- 配方常量与版本号住在共享层（`ALIAS_LINEAGE_RECIPE` / `ALIAS_LINEAGE_RECIPE_VERSION`），判决与形状同层，
  摘要函数留在主进程侧 —— 与仓内既有先例同规。
