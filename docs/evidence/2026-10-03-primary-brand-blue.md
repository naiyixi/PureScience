# 主色对齐 DeepSeek 蓝 #4D6BFE —— 真机读数（2026-10-03）

## 一、改了什么

| 位置 | 改前 | 改后 |
| --- | --- | --- |
| `src/renderer/src/assets/main.css:129`（浅态 `--primary`） | `oklch(0.56 0.2 264)`（换算 ≈ `#3569E7`） | **`oklch(0.5915 0.2202 269.6)`**（= 品牌蓝 `#4D6BFE`） |
| 同文件 `:197`（深态 `--primary`） | `oklch(0.74 0.13 264)` | `oklch(0.74 0.137 269.6)`（**同色相 269.6**、保持深态亮度、彩度略降） |

换算式（可复核）：`#4D6BFE` → oklch **L 0.5915 / C 0.2202 / h 269.6**；旧的 `#3569E7` → L 0.5596 / C 0.1994 / **h 264.05**
⇒ 差异不只是明暗，**色相差 5.5°**（旧值偏青）。全仓库 grep `4D6BFE` / `3569E7` ⇒ **除这两行外零命中**，改动是单点。

## 二、真实窗口读数（不是看样式表）

`e2e/certification/journal-metrics-panel.spec.ts` 里新增探针：创建一个元素取 `var(--primary)`，
**把它画到 canvas 上再读像素**——因为 Chromium 会把 `oklch()` 原样序列化（这一步我第一次写错过：只读
computed style 拿到的是 `oklch(...)` 字符串，证明不了任何像素），画布才是"按钮实际画成什么"的证据。

```
[panel-reading] --primary token: oklch(0.5915 0.2202 269.6) → paints as: rgb(77, 107, 254)
```
断言按住通道 ±2 容差比对 `rgb(77, 107, 254)` ⇒ **通过**。`#4D6BFE` = `rgb(77, 107, 254)` 逐通道相等。

截图（同一窗口、面板打开、主色开关处于按下态）：`docs/evidence/2026-10-03-primary-brand-blue.png`。

**同一轮附带复核的既有读数**（改名后全部仍成立）：`2 passed (7.7s)`，含指标面板的年份+来源、缺失写 `Unknown`、
筛选控件交互、以及 U4 的合并/别名读数。

## 三、如实标注的边界

- **改前那个数值是"换算值"不是"窗口实测值"**：我在改之前没在同一窗口里取过读数，所以 `#3569E7` 来自对旧 token 的
  换算（同一套换算公式，与本文件自洽）。**若需要改前的窗口实测值，得回退构建再跑一次**，本轮未做。
- **对比度**：白字（`--primary-foreground: oklch(0.985 0.005 264)`）压在新区上比压在旧区上**对比度略降**
  （品牌蓝更亮）。本轮只做了"主色是否是品牌蓝"的核对，**未做 WCAG 对比度实测**——若要严格口径，
  应按按钮实际字号/字重测一次对比度再决定是否微调 `--primary-foreground`。立案。
- 深态读数本轮**未单独取**（探针取的是当前主题的 token；本轮窗口是浅态）。深态改动与浅态同源、同色相，未取不假装已取。
