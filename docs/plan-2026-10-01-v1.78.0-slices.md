## 1. R3 每轮执行的文件证据（读入 / 写出 / 未捕获）

### 1.1 当前实情（本轮实测）

- **写出侧已存在**：`src/main/notebook/working-file-observer.ts`（观 `dataRoot` 下变化，`MAX_CHANGED_PATHS = 10_000`
  `MAX_FALLBACK_SNAPSHOT_ENTRIES = 50_000`，`EVENT_SETTLE_MS = 20`）；产出 `NotebookWorkingFile`
  （`src/shared/notebook.ts:285`），带 `changeKind: 'created'|'modified'|'removed'`（`:291`）。
  两个调用点：`src/main/notebook/kernel-executor.ts:56`、`src/main/notebook/execution-owner.ts:44`。
- **多会话同目录冲突**：`working-file-observer.ts` 内部 `activeByDataRoot` + `ActiveObservation.conflicted`——
  **只进内部状态，用户看不到**。
- **上限静默**：`changedPaths.size >= MAX_CHANGED_PATHS` 时**只是停止收集**（`:249`），运行记录里看不出"被截断"。
- **读入侧不存在**：全仓无"本轮读了哪些既有文件"的记录；`grep readFiles/readEvidence` = 0。
- **run 记录**：`src/shared/notebook.ts:335` `workingFiles: NotebookWorkingFile[]`；
  持久化 `src/main/notebook/repository.ts:102-132`（normalize）；编解码
  `src/main/notebook/run-document-data-paths.ts:43,51`；provenance 消费
  `src/main/artifacts/provenance-repository.ts:1063`（`hasOmittedFiles`）、`:2621`。
- **驱动是我们自己写的**（关键）：`resources/notebook/python_loop.py`（JSON 行协议走 `dup(1)`，
  `_BOOTSTRAP` 在 `:356` 执行，逐 cell `exec(compile(...))` `:438`）、`resources/notebook/r_loop.R`、
  `resources/notebook/repl_loop.js`；路径可用 `PURESCIENCE_PYTHON_LOOP` 覆盖（`kernel-executor.ts:107-108`）。
  ⇒ **Python 侧可用 `sys.addaudithook` 在进程内捕获 `open()`**，不需要任何原生/系统级组件。

### 1.2 切片

- **R3-U1（契约，纯类型 + 纯函数）**：新增
  `NotebookRunFileEvidence`：`{ read: NotebookReadFile[]; readStatus: 'captured'|'truncated'|'unsupported'|'unavailable';
  readReason?: <具名原因>; readTruncatedCount?: number; writeTruncatedCount?: number; directoryConflict?: 'shared-directory' }`。
  分类规则（纯函数，可测）：读路径落在本轮的 `created|modified` 集合里 ⇒ `kind: 'intermediate'`（本轮写出后又被读回），
  否则 ⇒ `kind: 'input'`（运行前**已存在**的输入）。`readStatus` 与 `writeTruncatedCount` 让"没捕获到"**永远可见**。
- **R3-U2（捕获，驱动侧）**：`python_loop.py` 装审计钩子，按前缀（内核 cwd = 数据目录 + 会话工作区）过滤并**去重**收集读打开，
  上限内返回；上限超出 ⇒ 只报计数与 `truncated`（**不回退成空**）。R/JS 驱动与"旧版打包驱动"⇒
  `readStatus: 'unsupported'` + 具名原因（例如 `driver-without-read-capture`），**不得静默当作"没有读入"**。
- **R3-U3（呈现 + 链路）**：运行证据面板并列三态（读入 / 写出 / 未捕获）＋截断计数与冲突提示（九语言）；
  读入清单进入产物 lineage（"这个结果用了哪几个既有文件"），沿用既有引用完整性规则；`hasOmittedFiles` 一类
  的既有"省略"语义与新三态**不重复计数**（同一事实只在一个字段里说一次）。

### 1.3 验收（真机）

① 一轮执行同时列出读入与写出，写出清单与磁盘一致；② 读一个超大目录触发上限 → 显示
「已截断 + 数量」而不是空清单；③ 两个会话同目录 → 两边证据都在且有冲突提示；④ 从产物反查读入清单能跳到对应文件；
⑤ **未捕获**态可被观察到（用一个不做读捕获的驱动跑一轮，界面必须显示具名原因，而不是干净的"无读入"）。

### 1.4 风险

- 上限与观察窗口语义变动会碰既有测试面；**不得**把观察改成常驻后台监控（仍只覆盖执行窗口）。
- 审计钩子必须**低开销**（只记 path 与 mode，不做 stat）；大目录读要能截断且可复现。

## 2. R6 内容寻址存储与去重

### 2.1 调查结论（本轮已完成，父计划要求的"第一步"）

- `ManagedFile`（`prisma/schema.prisma:141-160`）有 `checksum` / `storageKey` / `sizeBytes`，**没有内容块模型**。
- `storageKey` 是**存储根下的相对路径**（`provenance-message-snapshot.ts:41` `segments.join('/')`，
  `resolveStorageKey(root, key)`），不是内容摘要。审核快照也是同一形态（`reviewer/repository.ts:258-292`）。
- **全仓没有硬链接/内容寻址去重**：`grep -rn "link(|hardlink|contentAddress"` 在 `src/main/artifacts`、`src/main/files` = 0 命中。
  ⇒ 同一 PDF 多次导入/多版本**目前各占一份**（与父计划推测一致）。

### 2.2 切片

- **R6-U1（写路径调查 + 摘要落点）**：列出所有"把字节落盘"的入口（产物版本、托管文件、审核快照），
  确认哪些已带 `checksum`、哪些没有；产出一份**可复核的写点清单**（不是计划，是 `file:line` 清单 + 每个写点的
  内容摘要可得性）。
- **R6-U2（内容寻址存储层）**：以 `sha256` 为键的共享内容目录 + 引用计数；写入即"存在则复用"；
  迁移**可回滚**、历史数据**原地升级**。
- **R6-U3（去重报告 + 删除安全）**：界面给"省下多少 / 哪些文件共享同一内容"；删除必须能证明
  "别处仍引用"（引用计数可证明），否则不给删。

### 2.3 验收（真机）

① 同一 PDF 导入两次 → `du` 只增加一份；② 界面显示去重报告与共享清单；③ 删其中一个引用，另一个仍可打开。

## 3. R2 期刊实体与属性（含来源与提交收据）

- **实情**：`Reference`（`prisma/schema.prisma:474`）只有 `venue String?`、`sourceConnector`/`sourceRecordId`/`provenanceJson`；
  **无期刊实体、无属性表、无绑定指纹、无元数据修订号**。
- **切片**：U1 数据模型（期刊实体 + 属性 + 文献绑定，含来源/抓取时间/方法）；U2 「只写选中项、空值不覆盖」语义 +
  刷新入口；U3 提交收据（期望修订 → 已提交修订）与"已被他人修改"提示；U4 导出随行来源、「未知」与「空」区分。
- **风险**：**迁移只做一次**——与"文献智能筛选"在飞计划共用文献域；先确认该计划是否也改同表，
  若会改则**合并迁移**或把本片排到其后。属性数据来源属内容获取，**不得承诺覆盖率**。

## 4. R4 表格/结构抽取的恢复深度（最重，最后做）

- **实情**：已有且契约更严——`src/shared/pdf-table-extraction.ts`（按基线分行 + 按 x 间隙分列；`:394` 强制标签、

  无合并格、无多级/折行表头、无题注关联、无旋转与符号修复。
