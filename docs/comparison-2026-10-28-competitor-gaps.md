# 对标产品 v1.0.3 → v1.0.5 的迭代方向与我们的差距（2026-10-28）

结论先说：**我们不落后在「科学连接器广度」**（本仓 135 个 descriptor，比它列出的十来个更宽），
落后在**文献工作流、交付形态的对称性、长会话可读性、分发与更新**这四类「用户每天都会碰到」的面上。
它三天发了三个版本（v1.0.3 10-26、v1.0.4 10-27、v1.0.5 10-28），每版都是「若干可感知面 + 若干可靠性修复」的组合。

## 一 它在补什么（三版主题，均为发布说明原文归纳）

| 版本       | 主题                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **v1.0.3** | 7 个科学连接器（影像 TCIA、KEGG 通路、OmniPath、脂质、结构、癌症模型）；**文献库变成研究收件箱**（Semantic Scholar 引文发现：参考文献与引用它的论文、多源补充材料带进度与预览）；`.science` 包在 CLI 与本地 Web 也能导出/导入（不再只在桌面端）；译版 PDF 单栏重排；notebook 目录访问限制；Windows/沙盒/会话恢复/PDF 一轮可靠性修复                                                                                                                                                                                                             |
| **v1.0.4** | 安装体积显著变小；**独立 CLI 变成 MCP 服务器**（研究工具经本地 MCP 暴露给外部客户端，沿用既有权限）；长会话可读性（回合结束后中间消息折叠、工具组折叠成摘要）；**文献完整性检查**（有 DOI 的条目按需向 Crossref 查撤稿/更正，结果与检查时间落库）；明确写下「replay 复现记录步骤，不重新执行，solver-exact 等价性仍未保证」                                                                                                                                                                                                                     |
| **v1.0.5** | 连接器进入**原生数据源 API**（Europe PMC 布尔/核心/摘要检索带分页、HGNC、ChEA3、bioDBnet、Cellosaurus RDF、STR、NHANES/PhysioNet/openFDA/CTD 官方文件发现，全部 opt-in 且返回官方 URL 与 provenance）；**文献阅读状态**（未读/在读/读完 + 列 + 批量改 + 过滤）；`.science` 包**在浏览器里导出下载与上传导入**；**本地服务生命周期 hold 语义**（`start` 持有、`stop` 释放、`stop --force` 整体停）；用例画廊 + 已验证会话导入；手动更新入口与安装包定位；DOCX 报告保真（表格样式/边框/版式）；网络权限修复（全权限会话不再逐条弹窗、降级即断连） |

## 二 我们已经不落后的（本仓实测，避免误判）

| 能力       | 我们                                                                                                                                                                                 |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 科学连接器 | `src/main/connectors/descriptors` **135 个**（biomart、cellosaurus、chembl、clinical-trials、genes-_、genomes-_、expression-*…）；其中 europepmc / hgnc / cellosaurus / openfda 已有 |
| 文献与引用 | `src/main/references` 有**引用样式、期刊指标、PDF 标注的导出/导入**                                                                                                                  |
| 可追溯     | 轨迹包六段（工具调用/产物/契约）+ 成本矩阵 + `prompt usage` 对账 6/6                                                                                                                 |
| 多运行时   | 4 个框架（claude-code / opencode / codex / codebuddy）**各自解析到自己的二进制**，机检 4/4                                                                                           |
| 互操作     | A2A（agent card + `message/send` + `tasks/get`），独立进程客户端跑到 `state=completed`                                                                                               |
| 权限       | 权限门（`permission request received` / `permission decision`）已真机验过                                                                                                            |
| 中文场景   | 中文别名检索评测（PubMed 75.0% / OpenAlex 92.5% / arXiv 55.0%）、6 位中文医学专家 + 18 技能包                                                                                        |

## 三 真正的差距（按「用户能感知 × 我们能验证」排序）

| #   | 差距                                         | 我们的现状（代码级核对）                                                                                           | 它的做法                                                                    |
| --- | -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------- |
| 1   | **文献完整性检查**（撤稿/更正）              | `retraction` / `crossref` 检索命中 0                                                                               | DOI → Crossref，结果与检查时间落库，界面上只给一个短动作                    |
| 2   | **引文发现**（某文的参考文献与引用它的论文） | `semantic.scholar` 命中 **0**                                                                                      | Semantic Scholar 双向引文 + 补充材料多源下载/预览                           |
| 3   | **文献阅读状态**                             | `readingStatus` 命中 **0**                                                                                         | 未读/在读/读完，列 + 行内/批量 + 过滤                                       |
| 4   | **会话包的对称可用**                         | export/import 只在桌面路径，`web-service` 与 CLI 无入口（grep 为空）                                               | 桌面 / CLI / 浏览器三处都能导出下载与上传导入                               |
| 5   | **CLI 作为 MCP 服务器**                      | 应用内 14 个 MCP 工具 + HTTP 面；CLI 侧无对外 MCP 服务器                                                           | 对标产品 CLI 暴露研究工具给外部 MCP 客户端                                  |
| 6   | **长会话可读性**                             | 无「settled 折叠 / 工具组摘要」（`collapse` 只出现在数据源字段名里）                                               | 回合结束即折叠中间消息，运行中/等待/中断保持可见                            |
| 7   | **分发与更新**                               | Windows **未签名** NSIS（SmartScreen 未知发布者）；macOS 仅 ad-hoc 签名；有 `electron-updater`（generic provider） | Windows 代码签名安装包、Homebrew cask、独立 CLI tap、原位自动更新、体积压缩 |
| 8   | **用例画廊 + 可验证样例**                    | 无 use-case gallery（我们有技能市场，性质不同）                                                                    | 首页画廊，每条可导入**已验证**会话包                                        |
| 9   | **DOCX 报告保真**                            | 有 docx 能力（8 个文件），未见"表格样式/边框/版式"保真口径                                                         | 生成与预览都保持表格样式/边框/版式，另有模板化 Markdown→DOCX                |

低优先：ChEA3 / bioDBnet / NHANES / PhysioNet 四个原生源——我们 135 个 descriptor 已更宽，
这四个是补点而非补面，可按用户提及率再定。

## 四 差异化打法（红线：交付必须优于对标，不是平齐）

| #   | 不做成「它那样」，要做成                                                                                                  | 可核验的判据                                                          |
| --- | ------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 1   | 撤稿检查**写进证据链**：结果绑定到引用条目与 PDF 标注，导出报告时强制带「检查时间 + 来源 URL」，任一断言可回溯            | 一份报告里每个 DOI 都能点回 Crossref 记录；删掉检查记录则报告生成失败 |
| 2   | 引文发现带**中文源**（CNKI/万方可及范围内）与「为什么相关」的一段理由，而不是只列标题                                     | 同一查询里中英文各有命中，且每条附理由                                |
| 3   | 阅读状态与**项目进度**联动（未读但被正文引用 ⇒ 标黄提醒），这是它没有的                                                   | 项目里被引用却未读的条目会被点名                                      |
| 4   | 会话包内**含验证证据 + 成本/工具调用读数**，导入后可一键重放；在可验证子集上给出等价性证明（它明确说做不到 solver-exact） | 导入后的包能复现同一份读数，逐字段比对一致                            |
| 5   | CLI MCP 暴露的工具**全部走同一权限门与审计链**（它的说法是"沿用既有权限"，我们给可审计记录）                              | 外部客户端每次调用都在 `permission decision` 里留痕                   |
| 6   | 折叠之上加**每轮成本/耗时归因**（我们已有 `turnUsage`、p50/p90 读数），让"长会话为什么贵"可回答                           | 折叠后的摘要行能展开出该轮 token/耗时                                 |
| 7   | 签名与更新：**Windows 代码签名 + macOS Developer ID + 自动更新 + Homebrew tap** —— 纯工程与费用项，需拍板                 | 安装时无"未知发布者"，更新可原位完成                                  |
| 8   | 画廊里每个样例都是**真机跑出来的会话**，并附"怎么验证它"的一段说明                                                        | 点开样例能看到读数文件与原话                                          |

## 五 建议顺序

1. **先做 1、2、3（文献工作流三件）**：纯代码，复用现有 `references` 与连接器框架，2–3 天；
2. **再做 4、6（会话包对称 + 长会话可读性）**：4 需要动 web-service 与 CLI 入口，6 是渲染层；
3. **5（CLI MCP）**：要复用应用内 MCP 服务器与权限门，中等；
4. **7（签名/分发）**：需要账号与费用，等你拍板；这是唯一「花钱就能明显追平」的一项；
5. 8、9 随手做（样板与 DOCX 保真口径）。

> 口径提醒：本档只写差距与打法，不写对标产品名；引用其发布说明时只做事实归纳。
