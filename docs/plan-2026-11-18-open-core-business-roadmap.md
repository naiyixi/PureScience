# open core 双轨商业模式排期（B0 → B7）

前提（已核实）：我们是 **Apache-2.0**（`LICENSE` 实测）；参考产品 A 也是 Apache-2.0，且 **Ace 没有订阅**，收入来自托管推理
按量价差 + 支付通道成本。因此「学它做订阅」是伪命题；我们能守住的差异是**国产模型 + 中文场景 + 可私有化**。

## 收入三条线

| 线                  | 谁付钱                     | 我们卖什么                               | 现状                                               |
| ------------------- | -------------------------- | ---------------------------------------- | -------------------------------------------------- |
| L1 机构许可         | 医院科室、高校实验室、药企 | 私有化部署 + 组织席位 + 审计 + SSO + SLA | **零实现**（`src/main` 无 SSO/SAML/组织/审计导出） |
| L2 国产模型聚合计费 | 不想自管 key 的个人与机构  | 额度池、发票、模型白名单、按量结算       | 零实现（我们只支持自带 key）                       |
| L3 专家市场分成     | 中文医学专家/团队          | 签名专家包上架与分成                     | 已上线签名包，**无计费**                           |

## 硬边界（先定，避免自伤）

1. **不靠许可限制做企业版**：Apache-2.0 已发，功能阉割会被社区反噬 ⇒ 企业价值只放在「运维、合规、组织、服务」；
2. **私有化必须真离线可用**：不能暗中回连我们的服务；
3. **审计数据属于客户**：导出格式要给第三方能读（JSONL + 校验和），不锁进私有库。

| 单元                    | 动作                                              | 判据（真机）                                   |

## 依赖顺序（不能颠倒）

`B0.3 许可格式` → `B1.1 许可校验` → `B1.2 席位` → `B1.3 审计` → `B2.1 SSO` → `B2.3 私有市场` → `B3.1 额度池`。
理由：没有可离线校验的许可，席位与计费都无处安放；没有审计，机构过不了合规评审，SSO 做了也卖不动。

## 风险

- **Apache-2.0 下被二次分发**：靠商标与服务而非许可限制；企业客户买的是合规与支持；
- **私有化维护成本**：每个机构版本分支会拖死节奏 ⇒ 只发布**同一二进制 + 许可文件差异**，不做分支；
- **计费合规**：涉及代收代付与发票，需与实际开票主体对齐，先做机构对公结算，不做个人预付费池。
