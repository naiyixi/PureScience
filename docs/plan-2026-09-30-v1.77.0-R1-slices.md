## 2. 级别定义（诚实口径，写进契约）

保护级别按**最弱一面**判定，两面分别可读：

- `os-sandbox`：文件系统面（运行时写保护）**且** 网络出口面（允许表）同时成立。
- `network-allowlist`：只有网络出口面成立。
- `unprotected`：网络出口面未过滤（文件系统面即使有也降级，**降级原因具名**）。

`scope` 两个轴恒随快照输出，所以「级别降了但写保护还在」这件事在界面上读得到，不会被级别标签吞掉。

附记（实跑踩到的两件事，已修并留档）：

- **CI 车道红**：`scripts/ci/classify-pr-changes` 的 Windows 分类守卫按**文件内容**判定，`src/shared/execution-protection.ts` 只因注释里出现 `bash/powershell` 被判 Windows 敏感 → 改注释而非登记覆盖层（该文件不做 Windows 特有决策）。修于 `e20de0c4`。
- **审批路径的无条件 await 会挂死请求**：给 promise 顺序敏感的 broker 加一个无条件 `await`，会让调用方的同步 `respond` 早于挂起注册，请求永久挂起（vitest 表现为「零输出超时」）。修法：只在真正需要（请求带保护快照）时才 await，并补反向用例钉住「无快照请求的解析顺序不变」。

## 6. 真机验收待办（本片尚未做，必须在打包/开发版应用里逐条跑）

单测与 typecheck 只证明契约与接线没坏，**不等于**功能验收。以下五条仍待人工在应用里执行：

1. 设置 → 执行保护：读到四行矩阵（笔记本/终端/后台作业/远程主机）与两轴取值；OS 写保护行显示本机实际能力。✅ 入口：设置侧栏「执行保护」（网络下一项）。
2. 笔记本跑一个单元、终端跑一条命令：两次运行的证据行显示级别；关掉「网络 → 限制进程网络访问」再跑一次，级别下调为无保护，且矩阵页给出具名原因与修复路径。
3. 远程主机执行一次（`call_command`）：批准前卡上出现「本次执行无保护」，且**只有** 拒绝/本次允许 两个按钮；批准后作业详情出现「保护级别」行。
4. 无保护执行的默认档 = **拒绝**（`deny`，2026-10-01 拍板，与排期标题「远程默认拒绝无保护运行」一致；上一轮我先选的 `confirm` 偏离排期，已改回）：默认下无保护远程运行**不出卡、直接拒绝、不写入任何授权记忆**；把策略切「每次显式确认」后确认旧的项目/会话授权**不再**静默放行（会重新出卡）；再切「让记住的批准也能覆盖」，确认恢复静默。三种档的界面文案都写明「这是默认档」在哪一档。
5. 平台能力缺失路径：在无 OS 写保护的机器（Linux/Windows）上，矩阵显示「仅网络允许表」并给出「本平台无 OS 沙箱适配」的说明，而不是报错。
