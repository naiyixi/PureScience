# Plan 2026-10-21 · v2.17.0 SciBench-Local v1（设计先行）

> 前置：v2.16.0 能力契约 P0（`docs/plan-2026-10-21-v2.16-capability-contract.md`）。
> 铁律沿用：不为空壳造功能；每单元 commit + CI 双绿；设计先行项先拍板再动工。

## 1. 为什么现在做基准

现在能回答"这个版本没崩"，不能回答"这个版本更会做科学了吗"。SciBench-Local v0 只判 16 条规则、5 个案例、只读 trace，够当回归载体，不够当能力判据。

要回答的是三个问题：
1. 同一模型换 harness（Claude Code / OpenCode / Codex / CodeBuddy）差多少？
2. 加契约层到底带来多少提升？（对照：只给文档、只给工具名不给契约）
3. 便宜模型 + 好契约能不能打平贵模型？每任务多少钱？

## 2. 题库：40 题，判据与实现包无关

题源三路，全部可追溯到真实记录：
- **真实会话回放**：`docs/demo-verification/` 与验收历史里的真实任务（EGFR T790M 活性排名、SHANK2 变异解读、单细胞 QC、跨库一致性核对等）。
- **能力验收题集**（`PureScience能力验收题集`）里已公开的判据。
- **失败样本**：`docs/extreme-tests-2026-09/` 里真实失败并已修复的案例，反转为"必须仍然可过"的题。

每题只写**科学目标**，不写 API 名、不写库名（避免把答案写在题面）。难度按 40 题分 8 易 / 20 中 / 12 难，覆盖 6 类能力：
文献综合 · 数据核验 · 组学分析 · 结构与分子 · 统计与作图 · 交叉验证与溯源。

评分必须是**包无关的程序化断言**：ARI 对已知标签、marker 与 oracle 的重叠、数值容差、引用可验证性（DOI/PMID 真存在且内容匹配）、产物必须同时有图与生成脚本。用 Scanpy 还是 R 还是手写代码都算过——只判科学结果。

## 3. 六级原子检查（每题一组原子断言）

| 维度 | 判什么 | 例 |
|---|---|---|
| tool grounding | 是否真的调了该领域的工具（而非自造） | 结构任务必须出现结构来源（DB 或引擎）并标注 |
| data integrity | 输入有没有被误用/篡改/越界推断 | 排除的行不得渗入摘要统计 |
| object plumbing | 数据对象状态链是否成立 | 归一化→HVG→PCA→近邻图→聚类，缺一步即失败 |
| methodological robustness | 方法选择与参数是否可辩护 | 批次效应未处理即扣分并命名 |
| quantitative quality | 数值是否可复现、是否有 provenance | 每个数值带引擎/版本/参数/输入指纹 |
| biological plausibility | 结论是否超出证据 | 观察性证据不得写成"证明" |

Pass@1 = 该题**全部**原子断言通过；原子通过率单独统计（一题失败也仍有大部分断言通过，两个数都要报）。

## 4. 四臂消融（这是本版的核心证据）

同一模型、同一 runtime、同一种子、同一题库，只改"给了什么"：

| 臂 | 给什么 |
|---|---|
| baseline（A1） | 现状：skill 目录 + 文档 + 自由写代码 |
| doc-only（A2） | 额外注入完整 skill 文档正文 |
| named-no-contract（A3） | 工具名与签名可见，但无前置/产物/失败语义 |
| full-contract（A4） | 契约层全开（requires/produces/prerequisites + 预检建议） |

判读口径（写进 BENCHMARK）：若 A4 ≫ A2 ≈ A1，说明收益来自契约层而非文档；若 A3 ≤ A1，说明"只暴露工具名"会误导——这条对我们自己的产品叙事同样重要。

## 7. 诚实边界（必须写进 BENCHMARK 页）

- 自建题集天然偏向自家生态；对策：断言只锁科学判据，接受任何库的实现。
- 单机、单种子先跑；报区间而不是单一小数。
- 不宣称"覆盖领域"；这是**自我验收**，不是第三方排名。
- 任何一题若判据本身可被钻空子（例如产物存在但内容错），该题退回重写而不是放宽断言。
