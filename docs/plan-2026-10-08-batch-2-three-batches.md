# 批次 2：三条新能力面（2026-10-08 立，按用户拍板「按顺序都要开工」）

> 文档化队列已清零（见 `docs/plan-2026-10-08-batch-convergence.md` 的复核）⇒ 以下三条按**顺序**开工：
> **① 中文医学场景 → ② 溯源 → ③ 权限门**。每条先写差异化点（可执行判据），再核实源码/服务，再动手；
> 交付必须**优于对标而非平齐**，且必须**实机跑通**。同一时刻只推一个单元（拿判决就冻结推送）。

## 批次 ①·中文医学场景（先开工）

**目标**：把「中文循证」做成**可核验**的东西 —— 一条中文结论能追到**原文出处**，缺失就明说缺失。

**差异化点（都可写成断言）**：
1. **每条中文证据带发布机构 + 年份 + 原文出处**（不是只给一句结论）；出处不可解析时**具名拒答**，不编。
2. **缺失不写成阴性**（沿用 IEDB 那套口径）：查不到 ⇒ 明写「本次查询没有查到」，绝不写成「没有证据表明」。
3. **中文术语归一化**：同义异名（药名/适应证/机构名）先归一化再检索，并**说出归一化做了什么**。
4. **引用格式**：中文结论的出处按仓内既有 **GB/T 7714** 层输出（该层已存在，复用它，不另造）。

**第一步（先核实，不动手）**：
- 数据源必须**公开、可机器读取、可引用**。候选与其连通性（2026-10-08 实测，`curl -m 12`）：
  `chictr.org.cn`（中国临床试验注册中心）、`nmpa.gov.cn`（国家药监局）、`cde.org.cn`（药审中心）、
  `cma.org.cn`（中华医学会）——逐个看 **HTTP 码 + 是否提供机器可读接口**；只有网页 HTML 的，要判断
  「值不值得写一个只读抓取器」（本仓红线：服务方 HTML 不是稳定契约，抓取器必须**对形状变化具名失败**）。
- **不接受**：需要登录/付费墙/ToS 不明确的源（宁可这一批只做「术语归一化 + 出处格式」这两条不依赖新源的单元）。

## 批次 ②·溯源（全域「指出处」）

**目标**：把「每条结论指出处」从文献/记忆扩到**连接器读数与产物**全域 —— 工具读数也带**指纹与出处**，可离线复算。

**差异化点**：① 每条连接器结果带「服务 + 请求参数 + 响应体 sha256」；② 指纹可由**任何人离线复算**（给参数与响应字节即可核对）；
③ 产物与读数之间的引用链可遍历（哪个产物是哪个读数生成的）；④ 缺失指纹时**明说没记**（不填 0、不填 unknown 混过去）。

**第一步**：核实仓内既有 provenance 机制（产物/版本/校验和）能覆盖到哪一层，**不新造第二套**（先例：RO-Crate 的 sha256 已单一来源）。

## 批次 ③·权限门（会写盘的东西都要有门）

**目标**：把 per-env 授权那套口径推广到**每个会写盘的连接器/工具** —— deny-first + **具名拒绝** + **面板可见**。

**差异化点**：① 默认拒绝（不是默认允许后提示）；② 拒绝**具名**（说清是哪一条规则拒的、怎么开）；③ 面板上能看见「谁被授权了」并可**就地撤销**；
④ **不留空壳**：没有可写路径的工具**不加门**（先例：G3 归档的理由就是「为不存在的能力加 UI」）。

**第一步**：扫 `src/main/connectors/descriptors/*.ts` 里**真的有写路径**的工具（POST/PUT/上传/提交作业），列出清单再定门；
清单为空则本批按「架构已覆盖」结案并附 file:line。
