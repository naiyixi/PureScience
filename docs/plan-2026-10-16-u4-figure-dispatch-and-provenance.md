# U4 方案（v2.6.0 首单元）：插图理解**按图形类别分派** + 派生结果挂**既有**溯源面

> 会话认领（2026-10-16 20:0x–）。口径来自台账 §一百六十三 §五 与 §一百六十四 §五：**通用描述只覆盖最后一类，不许拿它冒充前三类**；化学一路**≥2 个独立引擎一致才算高置信**，低置信即拒答并给人工核对入口；派生结果挂 **模型 revision + 输入指纹**，换 revision/输入即标过期且可复算。

## 一 要接的缝（读源确认，不是推测）

- 插图候选现在由 `PdfService.figures()`（`src/main/settings/pdf-service.ts:330`）产出：每个候选带 `{page, index, bbox, caption?, captionSource, warnings}`，**没有任何理解步骤**。
- 该方法的解析注入点是 `this.options.parsePdf ?? parsePdf`（`open()` 里那一处在 `:187`）；它同时给出 `items`（带坐标的文字项）与 `images`（插图落位）⇒ **分类所需的两类证据本机已有**，不需要新模型。
- 派生结果的落点是**既有**的 `src/main/structure/structure-observation-journal.ts`（会话一条 JSON、主进程独占写、临时文件 + rename、有界 + `dropped`）与它的读侧 `artifacts/provenance-repository.ts`。**不另起一套**。

## 二 分派表（与 §一百六十三 一致；这里的「证据」是本机能拿到的）

| 类别            | 判定证据（都是确定性文本/几何）                        | 允许派生                           | 不许               |
| --------------- | ------------------------------------------------------ | ---------------------------------- | ------------------ |
| 化学结构式      | Scheme 号、化学词与取代基/试剂记号、产率形态           | OCSR ⇒ SMILES/InChI（**需引擎**）  | 用通用描述冒充     |
| 蛋白/生物结构图 | 图注/图内出现库号（PDB / UniProt），且带结构性上下文   | **查真实数据**绑定库号             | 用模型「读」出结构 |
| 图表/曲线/热图  | 轴/统计标记（IC50、%、HR、95% CI、p=、n=）与图内数值项 | 图内数值抽取，**每一项带页级几何** | 把数值算成结论     |
| 通用示意图      | 图注明写 示意图/schematic/flow/workflow                | 留给描述模型（本轮**不接**）       | 默认落到这一类     |
| 判不出          | 无信号 / 信号互相矛盾                                  | **具名拒答**                       | 猜一个类别         |

## 三 切片与验收（每片各自可跑、可读）

- **U4-a 分派器 + 具名拒答**（无模型即可落地）：纯函数，输入 = 图注文本 + 图内文字项，输出 = 判别联合 `{class, basis[], …}`，`basis` 逐条写明**是哪条证据判的**；判不出 ⇒ `undetermined` 带 `no-signals`/`conflicting-signals`。**验收**：单元用例逐类 + 反例（把「示意图」当默认落点必须红）；真机读一条真实 PDF 的图注/图内文字。
- **U4-b 蛋白一路**：把图注/图内的库号接到**既有**连接器（PDB/UniProt 读侧）取真实数据；库号不在图上 ⇒ 拒答，绝不生成一个。
- **U4-c 图表一路**：图内数值项逐条给 `{值, 页, 几何, 来源: 'pdf-text-in-bbox'}`；**不给结论**。
- **U4-d 溯源面接线**：把 a–c 的派生结果写成一条观察（复用 `recordStructureObservation` 的载体与串行化；新 kind 与既有判别联合一起收紧守卫），字段含 **模型 revision（化学）/连接器读数（蛋白）/几何来源（图表）** 与**输入指纹**（图候选的 bbox + 页 + 图注哈希），换输入即标过期、可复算。
- **U4-e 化学一路（OCSR）**：**≥2 个独立引擎一致**才给高置信；低置信 ⇒ 拒答 + 人工核对入口；结果挂引擎 revision + 输入指纹。

## 五 硬判据（不许松）

1. 判不出就拒答，**不设默认类别**；
2. 化学/蛋白/图表三类**不得**由通用描述兜底；
3. 派生结果**必须**带来源（模型 revision / 连接器读数 / 页级几何）与输入指纹；
4. 数值与结构**不给结论**，只给可核验的表示；
5. 录制永不把异常抛回调用路径（沿用既有载体的规矩）。

## 附：证据来源补齐（实测，U4 下一片的前提）

## 附二：U4-b 库号绑真实数据（真机读数）、面板读侧、以及 U4-e 的实测缺什么

### U4-b：图上读到的库号 → 库里**真取**的记录

**为什么**：蛋白/生物图上的 PDB / UniProt 库号此前只能原样带出（`accession-lookup-not-wired`）⇒「这是什么
蛋白」只能由模型去编。现在：端点契约 + 塑形（只取对外承诺的字段，库没给就**具名缺席**）+ 三种结果
（`resolved` / `not-found` / `unavailable`）；派生新增 `records` 变体，带**依据**（实验测定 / 预测）；查询实现
单开模块（`main/settings/accession-lookup.ts`），装配点注入 ⇒ 真机读数与生产走同一个函数。

**真机读数（本机直取，2026-10-17）**

| 库号             | 结果        | 真取回来的东西                                                                                                                                               |
| ---------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `pdb 1CRN`       | `resolved`  | 标题 `WATER STRUCTURE OF A HYDROPHOBIC PROTEIN AT ATOMIC RESOLUTION…`、方法 `X-ray diffraction`、日期 `19810728`；**响应里没有 `resolution`** ⇒ 缺席就是缺席 |
| `uniprot P00533` | `resolved`  | `AF-P00533-F1`、**`basis: predicted`**、`AlphaFold Monomer v2.0 pipeline`、`2025-08-01T00:00:00Z`                                                            |
| `pdb 9ZZ9`       | `not-found` | 服务答空列表（不是 404）—— 与「没查」分开                                                                                                                    |

**两处实测纠正**：① AlphaFold 端点对本应用的取数回过 **403**（同一路径 curl 是 200）⇒ 请求里如实带 UA 后
**200**；② 我最初拿 `9ZZZ` 当「不存在的号」，真机显示它**是一个真实条目**（沉积 2026-01-08、发布 2026-10-14）
⇒ 不是静默错绑，但也说明「自己以为不存在的号」不能当反例，改用 `9ZZ9` 才验出 `not-found`。

### 面板读侧：第三种 kind 真的渲染出来了

派生结果此前在「结构上下文」里是**空白行**（渲染层只算选择与测量 ⇒ 写得出、表示得了、但看不见）。现在三类
派生各有呈现：图表⇒数值（带印着它的那一行）；拒答⇒具名理由 + `detail` + 图上库号 + 缺什么；记录⇒条目号 +
依据 + 方法 + 日期 + 库自己的标题。指纹那一行标明是**记下来的输入指纹**（渲染层没有图注与图框内文字，不假装
能重算）。**没有可回跳的视图状态时不给「在视图里显示」按钮**（给了就是假交互）。i18n 14 键 × 9 语言。

### U4-e（OCSR 引擎）：实测缺什么，以及验收为何要 ≥2 台引擎

**本机实测（2026-10-17）**：`rdkit 2026.03.6` **在**、`torch 2.10.0` **在**；`tensorflow` / `decimer` /
`molscribe` / `onnxruntime` **全部缺席**；**识别资产（`structure-recognition-primary`）本机没有落** —— 数据根与
`~/Library/Application Support/PureScience` 下都没有 `engine-weights/`。**pip 可达**（实测 `decimer-2.8.0`
的 wheel 已下到本地）。

**验收口径（不放宽）**：化学结构式要有**≥2 台相互独立的引擎给出同一结果**才算高置信，单引擎不得冒充；置信
不足就**具名拒答**并发图。这条口径不变。

**解锁这条路的四步（按依赖顺序）**：① 装引擎（`decimer` 会带回 TensorFlow，或走 `molscribe`/ONNX）；
② 用产品自己的下载路径把 298 MB 识别资产落到缓存（`modelWeightPath(cacheDir, modelId)`）；
③ 把引擎接进派生路径（子进程 + IPC，推理结果带**模型 revision 与输入指纹**，与现有 `figure-derivation` 那条
规矩一致）；④ 在真实结构图上验证两台引擎一致 —— 单台或两台不一致都必须**具名拒答**。

**当前状态**：化学结构式一路**照旧具名拒答** `recognizer-unavailable`（缺的是引擎本身），本版没有、也不会
用单引擎或通用描述冒充它。
