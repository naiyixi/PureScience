## 1b. K2-U2 设计（2026-10-01 侦察后补，实施前先读这段）

**已确证的两件事（决定这一片能不能做成「真矩阵」而不是装饰）**

| 事实 | 证据 |
|---|---|
| **守门技能概念真实存在**（U3 的验收③可以成立，不必新建概念） | `skill-catalog.ts:723 withoutAlwaysOnSkillIds(disabledIds, skills)`：按 `isSkillAlwaysOn(skill.source)` 判定，**全局**过滤掉 always-on 技能的禁用意图；文件注释明说「只被一条路径遵守的闸门比没有闸门更糟：listing、materialization 与面向智能体的目录都问这里」 |
| **有明确的落地执行点**（矩阵值必须在这里生效） | `agent-runtime-manager.ts:663 materializeAgentSkills(settings, configRoot, forcedSkillIds)` → `skills.materializeSkills(configRoot, settings.disabledSkillIds ?? [], forced, trusted)`；技能文档按**框架目录**物化（框架可见的技能在各自目录下），因此「按智能体」的差异有处可落 |

**数据形状（拟）**：`settings.skillAvailability?: Record<string, { disabledSkillIds?: string[] }>`，键为**目标 id**（框架 id 或专家/specialist id）。写入时过 sanitize：未知目标丢弃、always-on 技能 id 一律剔除（沿用 `withoutAlwaysOnSkillIds` 的同一判定，**不许另写一份**）。

**必须同时遵守的四处**（漏一处 = 矩阵只在界面好看）：`skill-catalog.ts` 里 `withoutAlwaysOnSkillIds` 的四个调用点（125/145/165/229 的 listing/materialization/agent-facing 目录）+ 详情页（268）。

**验收②的真机取法**：勾掉某技能在某框架/专家下的可用性 → **跑一次该目标下的真实会话**，确认该技能不在该会话可见的目录里（比对物化目录里的技能文档清单），且**在另一个目标下仍然在**（差异必须两向可证，只证「消失了」不足以证明是按目标生效）。

**风险与收口**：这一片会触及会话装配与物化路径，属半迁移风险区——**一个单元内做不完就只落 `wip/k2-availability-matrix` 临时分支**，默认分支保持绿（`references/contract-inventory-ripple.md`）；UI 先于接线落地时，控件必须**不可点**或用「未生效」措辞，禁止出现改了设置却什么都不影响的开关。

## 2. 差异化红线（逐条可在真机核验）

1. 分数**当场可复算**：同一描述在离线状态重算一致（评分为纯规则），且列出「缺什么」而不是只给一个数。
2. 矩阵不是装饰：勾掉之后**在真机会话里**该技能确实不再加载（这条必须真机跑一次）。
3. 空值一律有词：「未知」不等于留白。

## 3. 真机验收（与排期一致）

| # | 断言 |
|---|---|
| ① | 自带技能与本机技能分别打开详情，触发质量分与其「缺什么」逐条列出，且同一描述离线重算一致 |
| ② | 矩阵每个智能体/专家一行；勾掉某技能后，**跑一次该专家会话**确认该技能不再加载 |
| ③ | 守门技能显示为不可关闭并给出原因（若无此标记，如实记为「本仓无守门标记」并撤下该断言）|
| ④ | 许可证字段为空时显示「未知」而不是留白 |

## 4. 明确不做

- 不引入外部模型给技能打分（评分的价值就在于**本地确定性**）。
- 不把发布方自评分搬进来（对标做法；我们展示的是你自己能复算的东西）。

## 5. 诚实边界

- U2 的矩阵接线会触及会话装配路径，属**半迁移**风险区：若一个单元内做不完，只落 `wip/<slice>` 临时分支，默认分支保持绿（见 `references/contract-inventory-ripple.md`）。
- ③ 若「守门技能」标记不存在，**不新建概念来满足断言**——按排期如实标注为「本仓无此标记」并撤下。
