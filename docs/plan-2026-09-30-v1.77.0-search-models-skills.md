## 1. 差异化红线（本批交付判据，逐条可在真机核验）

1. **「没找到」必须能自证是「没有」还是「没覆盖」**：检索与本地解析两侧同一条规矩——覆盖率、陈旧度、被截断的预算都要能在界面上读到，且写进响应证据。
2. **未验证内容绝不展示**：目录/制品校验失败时**具名失败 + 一条都不显示**，绝不静默降级成「展示未验证条目」。
3. **每个功能级模型必须写出回落路径且回落可查**：模型不可用/结果不明确 → 走确定性默认；该次回落要留痕（可查、可导出）。
4. **卸载本地资产不得删除派生结果**：删权重后派生结果仍可读；重装必须能命中本地缓存或给出明确下载量，不得重复下载。
5. **批量操作可停、可续、可回滚**：任何半装状态都必须可恢复；应用退出后重启要能说清上次队列停在哪。
6. **市场安装零执行**：安装期不执行来自包的脚本/可执行文件，且安装前显示将写入的路径清单（比对标产品「不运行包内脚本」更严：把清单也摊开）。
7. **本地可用性优先**：等价能力一旦落到本地（检索索引、解析模型），**断网可用**是验收项，不是加分项。

## 3. 逐片详情

### S1 检索作用域条与文件域分域 —— v1.77.0

- **目标**：命令面板顶部给出一排作用域芯片（全部 / 消息 / 会话 / 项目 / 上传文件 / 生成文件 / 文献库 / 标注），每个芯片显示**本类命中计数**；文件域一分为二，并在芯片区域写明「上传文件＝名称+已索引正文；生成文件＝仅名称；未索引不计入」。
- **我方现状与差距**：
  - 作用域枚举只有 `sessions | messages | files | literature | annotations`，无上传/生成之分：`src/shared/global-search.ts:26-33`。
  - 契约与数据面其实已够用：请求已带 `role/extensions/referenceTypes/since/until/cursor`（`src/shared/global-search.ts:52-72`），响应已带 **per-scope counts + scan 报告 + notes**（`src/shared/global-search.ts:244-256`），文件读取已按来源分流（`src/main/search/file-text-reader.ts:1-48`，`source: 'artifact' | 'upload'`），文件域命中退化为名称/路径时已会加 note（`src/main/search/global-search-service.ts:262-302`）。
  - 缺的是**界面**：当前只有 3 个下拉筛选，没有作用域芯片（`src/renderer/src/components/global-search/GlobalSearchDialog.tsx:1077-1160`），而且文件域只有一个 scope（`global-search-service.ts:262` 单口 `listFiles`）。
  - 界面文案侧已有「文件仅按名称匹配」的诚实提示键：`src/renderer/src/i18n/en.ts:2822`（`gs.contentFilesNameOnly`）。
- **差异化点（必须优于对标）**：对标只给一行静态说明；我们给**逐类实时索引实情**——每个芯片在计数旁显示该类本次扫描覆盖的上限/是否被截断（复用 `scan` 与 `notes`），点开能读到「为什么这条命中」（复用现有证据行：query/terms/snippet/指纹，`GlobalSearchDialog.tsx:807-925`）。即：**对标告诉你范围，我们告诉你覆盖**。
- **验收（真机断言）**：在打包/开发版应用里，对同一关键词：① 切换每个芯片，芯片计数与列表条目数一致；② 「上传文件」组能命中上传文档正文中的词，「生成文件」组对同一正文词**不命中**且界面明确写出不是「没有」而是「未索引/仅名称」；③ 当会话/文件预算被打满时，界面出现被截断提示且提示里的数字等于响应 `scan` 的数字；④ 点任一命中能展开证据行并显示指纹。
- **风险/依赖**：作用域枚举扩项会牵动 `resolveSearchScopes`、pin 描述串与既有测试面：`src/shared/global-search.test.ts`、`src/shared/global-search-paging.test.ts`、`src/main/search/global-search-service.test.ts`、`src/renderer/src/components/global-search/GlobalSearchDialog.test.tsx`、`e2e/certification/palette-commands.spec.ts`——迁移要**向后兼容**（旧 pin 的 scope 串仍可解析、仍可验证）。无外部依赖。

### S2 检索高级筛选面板与可自证筛选集 —— v1.77.0

- **目标**：一个「高级筛选」入口收纳：作用域、项目/集合、时间窗（不限/最近 7 天/自定义）、发送者、格式、文献类型、**结果排序**（相关度 / 时间）；筛选集可保存、命名、复用，并能在结果摘要行上**自证**。
- **我方现状与差距**：请求契约已支持时间窗与多类过滤（`src/shared/global-search.ts:52-72`），但界面**完全没有时间窗与排序控件**（`GlobalSearchDialog.tsx:1077-1160` 只有 3 个 select，`grep` 全文件无 `since/until`）。已有的「保存的筛选集」是 pins（`src/shared/global-search-pins.ts:150-176`，`GlobalSearchDialog.tsx:1166-1250`），且已有机器稳定描述串 `describeGlobalSearchFilters`（`global-search-pins.ts:160-176`）——**这是对标产品没有的东西**。
- **差异化点**：对标有「结果排序」但筛选集是**匿名状态**；我们把筛选集做成**可命名、可复现、可自证**的实体：应用一个 pin 后，摘要行给出该 pin 的机器可读描述（scopes/project/since/until/role/extensions/referenceTypes），并且结果里的证据行仍可**验证命中**（块指纹未变才算通过）。即：**对标能筛，我们能证明这批结果是在什么条件下得到的**。
- **验收（真机断言）**：① 设「最近 7 天 + 仅我发送 + 只表格格式」后，列表条数小于不限时间的结果，且摘要行出现的条件串与界面上的选择逐项对应；② 保存为 pin 后重开面板应用，结果与保存时一致；③ 把某条命中所在会话改动后再点「验证」，出现「证据已变化/未找到」而非静默通过；④ 清空筛选后结果集回到初始条数。
- **风险/依赖**：与 S1 共用同一面板与 i18n（9 种语言字典需同步；**本任务不碰正在被并发编辑的字典文件**，实现时统一改）。无外部依赖。

### M1 模型用途分域 + 功能级模型位 + 真检测 + 回落留痕 —— v1.77.0

- **目标**：设置→模型页按**用途**分区：当前模型（对话）、**功能模型**（能力自动选择、文献归类等）、**本地解析模型**（壳，内容由 M2 填）。每个功能行必须展示：实际生效的模型、**回落路径**、以及一次**真实检测**（有耗时与用量，不是只有通过/失败）。
- **我方现状与差距**：
  - 我们只有「场景模型」三个：`session-detail | subagent | review`（`src/shared/settings.ts:344-350`），UI 在 `src/renderer/src/pages/settings/ProvidersPanel.tsx:362-379`；另有视觉模型中继 `ProvidersPanel.tsx:384-393` 与每场景推理强度（`ScenarioModelSelect.tsx:35-80`）。
  - **没有**「功能级模型」这一层：全仓 `grep -rn "classif" src` 的命中都是无关语义——错误分类（如 `src/main/settings/validate.ts:259` `classifyStatus`、`:269` `classifyFetchError`）与连接器描述符措辞——没有任何「为某个功能选一个模型」的概念。
  - 模型服务的 CRUD/连通性测试已存在（`ProvidersPanel.tsx:120-345`，`ProviderForm.tsx`），可以复用成「功能模型」的选择器与检测按钮。
- **差异化点（必须优于对标）**：对标只说「首个服务会自动用于这两项功能」+ 一句隐私边界；我们做到**可审计**：① 每个功能行显示「本功能当前使用 X（来自服务 Y）；不可用时回落到内置确定性策略 Z」；② 检测按钮跑一次**真实往返**并显示实际耗时与用量（对应我们的 token 用量设施）；③ 每次回落写入一条可查事件（会话/设置里能翻到「这次归类为什么没用模型」）。即：**对标告诉你用了哪个模型，我们告诉你为什么、花了多少、失败时走了哪条路**。
- **验收（真机断言）**：① 不配任何功能模型时，功能仍工作，且事件区能查到「按默认方式执行」；② 给功能模型指一个不存在的模型名，点检测 → 界面**具名失败**且不改变功能行为；③ 用可用模型检测 → 显示通过 + 真实耗时（>0 且与实际等待相称）；④ 检测通过后触发一次真实归类/能力选择，事件区出现「用模型 X 完成，未回落」；⑤ 运行中断网触发一次 → 事件区出现「模型不可达，回落默认方式」，功能结果仍然产出。
- **风险/依赖**：功能模型若与主对话共用同一服务与密钥（对标产品如此），必须在 UI 说清**共用**还是**独立**，避免用户以为换了密钥；密钥删除策略沿用现有「移除服务会恢复默认」的既有语义。

## 4. 排序理由（为什么这样切）

1. **先补「可见性」而不是「新能力」**：S1/S2/K2 都是**已有数据面 + 缺界面**（counts/scan 已在响应里、评分器已在、筛选契约已在），单版内可做完且真机可验；对标产品在这三处只是「有」，我们能做到「有且能自证」。
2. **M1 先于 M2/M3**：分域是**概念与信息架构**，成本低、可立刻消除「三个模型页」这一最显眼差距；而本地解析模型是重活（下载/校验/运行时），把它排在 M1 之后，避免 v1.77.0 被一个 235 MB 级产物拖住。
3. **K1a 排队首但带硬依赖**：市场是三项里最大的**内容+机制**缺口，机制我们可以复用现有专家市场的签名/sha256/批量安装设施，**内容**依赖官方目录发布；因此先做「只读纵切 + 单条安装」，并在片内写明降级路径，不让目录未就绪变成发版阻塞。
4. **S3 放 v1.78.0**：索引是唯一会动存储与启动路径的重活，它必须在 S1/S2 的界面契约稳定之后做，否则会返工两次。
5. **M3 放更晚**：收益高但成本/风险同样高（新增运行时、大权重、内存受限），且它依赖 M2 的资产面先稳定。

## 5. 明确不做 / 不作承诺

- 不承诺技能目录**条数**（内容供给是发布工作，不是代码量）；不把「对标有 525 条」当作我们的验收指标。
- 不照搬任何对标文案与命名（作用域、分类、筛选label 用我们既有术语体系）。
- 不做「安装期执行包内脚本」这种便利（红线 6）。
- 不在本批引入任何新运行时依赖进主包；本地推理运行时按需下载并校验。
- 本任务不改产品代码/CHANGELOG/README，不 commit/push。

## 7.2 逐片详情

### R1 执行保护级别一等公民 —— v1.77.0

- **目标**：任何执行面（笔记本 / 终端 / 后台作业 / 远程主机）在**运行前**就显示它将以什么保护级别运行，并把该级别写进这一轮的执行证据；无保护只能显式选择并留痕。
- **对标做法（证据）**：它的保护按平台分型且**以错误消息收场**——macOS 侧会报「沙箱服务不可用」，Windows 侧会报「沙箱组件缺失，请重新安装」「沙箱网关端口不可用，请重新设置」「需要管理员进行设置」；并在远程命令的审批文案里**自述**「以你在该主机上的账户身份运行，且不在沙箱中」。即：有沙箱，但不是一个可查询的保护矩阵。
- **我方现状与差距**：
  - 网络侧只有**应用级允许表**：`src/shared/egress.ts:1`（对 notebook/repl/shell 子进程的域名允许表）、分组开关与审批：`src/shared/egress.ts:110,127,146`；存储与 IPC：`src/main/settings/repository.ts:1286-1293`、`src/main/settings/application-commands.ts:173,335`。
  - 包/环境变更只有**模式匹配识别**（不是隔离）：`src/main/notebook/managed-runtime-guard.ts:21-40`。
  - 全仓**没有**我们自己的 OS 级执行沙箱实现：`grep -rn "sandbox" src/main` 只命中「窗口 `webPreferences.sandbox`」（`src/main/windows.ts:70`，渲染进程选项）与「把沙箱开关传给某个智能体框架」（`src/main/agent-framework/codebuddy.ts:179-183`），二者都不是我们给笔记本/终端提供的隔离能力；也没有随包的原生沙箱组件。
  - 远程执行侧：`src/main/compute/ssh-runner.ts:242` 只保证「密钥不上命令行、临时脚本即删」，与保护级别无关。
- **差异化（必须优于对标）**：① 保护级别进**执行证据/产物 provenance**：每个产物能回答「它是在哪一级保护下产生的」；② 运行前展示 + 可查询的**保护矩阵**（平台 × 执行面 × 当前实际级别），把对标的一串「组件缺失/需管理员/不在沙箱中」变成可读状态；③ 远程执行**默认拒绝**无保护运行（或要求显式确认并留痕；标尺是不静默）。
- **验收（真机断言）**：① 笔记本/终端/后台三种执行面各跑一次，运行前都能读到保护级别的当前取值与来源；② 把网络允许表关掉再跑一次，产物证据里的级别随之下调且界面给出具名原因；③ 远程主机上执行一次，若该路径无法提供沙箱，必须在批准前明确写出「无保护」并在执行证据里留痕；④ 平台能力缺失时，界面给出可执行修复路径而不是只报错（对标只报错）。
- **风险/依赖**：OS 级沙箱本身（seatbelt/AppContainer 类）是**新增产物**，本片**不引入**原生依赖进主包——本片只做「级别的观测、展示、留痕与默认拒绝」；真正的隔离能力另立片（可作为 R1b，v1.79.0+，需要原生组件与跨平台验证）。

### R2 期刊实体与属性（含来源与提交收据） —— v1.78.0

- **目标**：文献的「期刊」不再是一个自由文本字段，而是一个可归属、可带属性、可审计的实体：属性有来源与时间，元数据改动有修订号与提交收据。
- **对标做法（证据）**：数据模型里有**期刊实体**（规范名、别名、ISSN 集合、外部 id）、**期刊数据项**与**文献↔期刊绑定**（带身份指纹与版本）；界面有「重新加载期刊属性」，并自述「只保存选中的属性；空值不会覆盖」；另有元数据提交收据表（操作 id + 期望修订 + 已提交修订）。
- **我方现状与差距**：`prisma/schema.prisma:474` 的 `Reference` 只有 `venue String?`、`sourceConnector`/`sourceRecordId`/`provenanceJson`；**没有期刊实体、没有属性表、没有绑定指纹、没有元数据修订号**（全文无 journal 相关模型或字段）。
- **差异化**：① 每条属性带**来源 + 抓取时间 + 方法**，界面上「来源」与「值」同屏；② 「只写选中项」「空值不覆盖」写进产品语义（这是对标的优点，我们照做但要求**可复核**）；③ 元数据改动给**提交收据**（期望修订 → 已提交修订），并发编辑不再靠「后写覆盖」；④ 「未知」与「空」在界面与导出里区分开（对标这两态混在一起）。
- **验收（真机断言）**：① 导入一批文献后，期刊实体被归并（同名不同写法的期刊归到一个实体），属性显示来源与时间；② 只勾选一项属性刷新，其他字段**字节未变**（比对摘要）；③ 属性为空的来源不得覆盖已有值，界面显示「未获取」而不是写入空；④ 用两个入口同时改同一文献的元数据，后者得到「已被他人修改」的收据提示而不是静默覆盖；⑤ 导出文献清单时属性来源随行导出。
- **风险/依赖**：一次数据模型迁移 + 属性数据来源（外部检索）属内容获取，**不得承诺属性覆盖率**；与「文献智能筛选」在飞计划共用文献域，避免同时改同表（迁移排在筛选切片之后或合并一次迁移）。

### R3 每轮执行的文件证据（读入 / 写出 / 未捕获） —— v1.78.0

- **目标**：每一轮执行都留下「它读了哪些既有文件、写了哪些文件、哪些没捕获到」的清单，未捕获是**一等状态**而不是沉默。
- **对标做法（证据）**：随包带一个独立的文件证据 worker 资源，数据根下另有「执行文件证据」与「笔记本输入」两个目录，说明它把每轮执行的输入/输出当成可持久检索的记录；其路线图自述证据可能「未捕获」，但没有把未捕获做成可见字段。
- **我方现状与差距**：只有**工作目录增量观察**：`src/main/notebook/working-file-observer.ts:1-25`（上限 `MAX_CHANGED_PATHS = 10_000`、多会话同目录冲突标记 `:21`，产物类型 `src/shared/notebook.ts:284`）；产物侧有 inputs/outputs 证据：`src/shared/artifact-provenance.ts:318,360`。差距是：**没有「本轮读入了哪些既有文件」的清单**，也没有「未捕获」的显式表示（对标的 worker 就是干这个的）。
- **差异化**：① 读入清单进入产物 lineage（「这个结果用了哪几个既有文件」），与我方已有的引用完整性规则一致；② **未捕获**显式呈现（例如脚本通过原生扩展读写、或超上限被截断时，写明「未捕获/已截断」而不是当作没有）；③ 多会话同目录的冲突标记从内部布尔变成用户可见的诚实提示。
- **验收（真机断言）**：① 一轮执行的证据面板同时列出读入与写出，且写出清单里的文件与磁盘一致；② 故意让脚本读一个超大目录触发上限，界面显示「已截断 + 数量」，不是空清单；③ 两个会话同时写同一目录，界面出现冲突提示且两边的证据都保留；④ 从产物反查读入清单，能跳到对应文件。
- **风险/依赖**：观察器与上限迁移会影响既有测试面；不得改变「不后台常驻监控」的既有约束（观察只覆盖执行窗口）。

### R4 表格/结构抽取的恢复深度 —— v1.78.0

- **目标**：在保留我们「候选 + 出处 + 可用性审计」契约的前提下，把版面恢复能力补到能处理真实论文表格：标线/矢量图形、合并格、多级与折行表头、题注关联、旋转与符号修复；并让「为什么这块被判不是表」对用户可见。
- **对标做法（证据）**：随包带一套约 44 个模块的版面/表格结构层，覆盖标线边缘分类与聚类、逐格文本与合并单元格、题注分组与图表关联、页几何、旋转判定、符号文本修复，以及针对具体稿件版式的多种网格恢复（重复表头、折行汇总、带框两级表头、分段记录、规则表头等）；它以「来源文本必须支持」为门槛，并把目录页、补充材料清单、机构署名等**假阳性规则写死在代码里**；同时随包带一个自述为「离线实验、不是生产抽取器」的本地模型脚本。
- **我方现状与差距**：
  - 已有且**契约更严**：`src/shared/pdf-table-extraction.ts:23-28`（两种方法：按基线分行 + 按 x 间隙分列；无坐标时退化为空白串分列）、`:240` 抽取入口、`:394` 强制标签、`:400` 可用性审计；图侧 `src/shared/pdf-figure-extraction.ts:1-16`（足够大的图片放置 + 样式自己写的标签）。
  - 差距是**恢复层级只有一层**：没有标线/矢量图形分析（`src/main/settings/pdf-service.ts:1-6` 只做文本、书签、图片对象与词频扫描；`:425` 的 operator list 只服务图片检测）、没有合并格、没有多级/折行表头、没有题注关联、没有旋转与符号/连字修复、没有表格脚注与上标处理。
- **差异化（必须优于对标）**：① 恢复能力补齐后仍**只输出候选**，并给「为什么不是表」的**用户可读理由**（对标的同族规则写死在代码里，用户永远看不到）；② 对**未解析区域**具名（「此页有 3 处无法判定」），而不是静默漏掉；③ 候选取信分级进入界面与导出（我们已有 `PdfTableConfidence`，把它接到 UI 与审计），并进入引用完整性规则。
- **验收（真机断言）**：① 一篇带三线表的真实论文：面板给出的行列与人工核对一致，单元格归属正确；② 一篇带合并格与两级表头的表格：合并格被标注（不是把合并内容重复进每个格子）；③ 补充材料清单页/目录页**不产生表格候选**，且界面写明「已按理由排除」；④ 表格跨页或旋转页：候选要么正确，要么具名「未能判定」，不得给出错列；⑤ 给智能体的命令结果与面板读取结果**一致**（同一文件同一方法，不许两套答案）。
- **风险/依赖**：本片是本层面**最重**的一片（新增启发式与其维护成本），必须**不做**：不引入大权重（对标的本地模型自述只是实验）；体积控制与页面级预算（大页 PDF 的 CPU/内存上限，8 GB 机器上必须可取消）；与在飞的预览/标注工作互不触碰。

### R5 抽取质量语料与可自跑回归 —— v1.79.0

- **目标**：把「抽取质量」变成可复核的东西：一份随包的难例语料 + 一个**应用内可跑**的自检，跑完给「通过 / 退化 / 未覆盖」，退化即阻断发版。
- **对标做法（证据）**：一个回归脚本对抽取记录做**全字段比较**（含源几何、跨度与备注），并对裁剪图做**解码后像素级**比较（避免压缩差异误报），支持批次、baseline/candidate 前缀、文档清单文件。
- **我方现状与差距**：只有单测（`src/shared/pdf-table-extraction.test.ts`、`src/shared/pdf-figure-extraction.test.ts`），**没有跨文档语料、没有记录级/裁剪图级回归、没有应用内自检**；也没有把「哪类难例在退化」这件事报表化。
- **差异化**：① 语料随包且**自我说明**（每条用例带难例类名、期望结构、以及当前差异）；② 自检在**应用内可跑**（用户/开发者同一入口），不是只在 CI；③ 报告三态诚实（未覆盖不当作通过）；④ 与「发布前证书」衔接（退化阻断）。
- **验收（真机断言）**：① 应用内跑一次自检，报告给出通过/退化/未覆盖三态计数；② 人为把某个恢复规则改坏，自检报出**具名用例**与该用例的差异字段；③ 新增一条语料后基线更新流程可复现（同输入两次跑出同一基线）；④ 报告可导出。
- **风险/依赖**：R4；语料必须是自造或已授权可再分发的样本，**不得搬用任何具名文档/数据进仓库**。

### R6 内容寻址存储与去重 —— v1.78.0

- **目标**：相同内容的文件在磁盘上只占一份，且「省了多少、哪些重复」可以在界面读到。
- **对标做法（证据）**：数据模型里有内容块实体（去重存储的形态），另有托管文件版本的写操作台账。
- **我方现状与差距**：`prisma/schema.prisma:141` 的 `ManagedFile` 有 `checksum`/`storageKey`，但**没有内容寻址的块模型**；同一 PDF 多次导入/多版本看起来各占一份（`storageKey` 语义需先调查，见风险）。
- **差异化**：① 去重**报告**（本机省下多少、哪些文件共享内容）——对标有机制但没有「省了多少」的可见性；② 删除某文件时必须能证明「别处仍引用」，否则不给删（引用计数可证明）；③ 与存储告警/迁移联动（8 GB 机器上直接收益）。
- **验收（真机断言）**：① 同一 PDF 导入两次，磁盘占用只增加一次的量（`du` 前后对比）；② 界面显示去重报告与共享该内容的文件清单；③ 删除其中一个引用，另一个仍可打开（内容未被删）。
- **风险/依赖**：**先调查**现有存储层是否已有硬链接/引用计数（本片第一步是调查而不是重写）；迁移必须可回滚，历史数据要能原地升级。

### R7 远程计算凭据托管 + 认证/作业操作台账 —— v1.79.0

- **目标**：远程主机的凭据有受管存储，认证与作业提交都留下可查台账。
- **对标做法（证据）**：数据模型里有计算凭据、认证操作、作业操作三张表（即「哪次认证、哪次提交」都是记录）。
- **我方现状与差距**：`prisma/schema.prisma:452` 的 `ComputeHost` 有主机但没有凭据模型、没有认证/作业操作台账；密钥只按「不上命令行、临时脚本即删」处理：`src/main/compute/ssh-runner.ts:242`；主机配置沿用既有 ssh 配置解析 `src/main/compute/ssh-config.ts`。
- **差异化**：① 认证台账可查（何时、哪台主机、结果、是否复用已有会话）；② 凭据**失效探测**与提前告知（对标是失败才知道）；③ 「没有残留临时文件/后台进程」作为可断言语义。
- **验收（真机断言）**：① 提交一次远端作业后，台账里有认证与作业两条记录且时间与真实一致；② 故意让凭据失效，下一次提交前就有提示（而不是作业失败后）；③ 取消作业后台账记录取消结果；④ 执行结束后目标机上无残留脚本（人工核验路径）。
- **风险/依赖**：凭据存储必须走既有系统凭据设施，不得新增明文落盘路径；与 R1 的保护级别共用同一展示面。

### R8 制品代码的结构级重建 —— v1.79.0+

- **目标**：把「重建产出代码」从文本拼接升级为结构级重建，并让重建等级可读。
- **对标做法（证据）**：随包带四种语言的语法解析资产（WebAssembly 格式，附许可证与来源清单），说明其代码重建与代码结构理解依赖语法树。
- **我方现状与差距**：`src/shared/artifact-code-reconstruction.ts:1-11` 只有重建契约（code/language/generatedAt/frameworkId/model/sourceTruncated），**全仓没有语法解析资产**（`tree-sitter` 只在 `src/shared/run-dependencies.ts` 作为依赖名出现）。
- **差异化**：① 重建结果永远标注「模型重建 ≠ 执行记录」（我们已有更严的重放契约，直接把该语义接到重建）；② 结构级重建能保住函数/块的边界，且**无法重建的段落具名**；③ 解析资产随包带许可证与来源清单（可审计的第三方资产）。
- **验收（真机断言）**：① 对同一份历史制品重建，输出按结构分段且语法可解析；② 源被截断时明确标出截断位置与影响范围；③ 重建结果不能通过任何「已验证复现」标记（回归断言）。
- **风险/依赖**：新增随包资产（体积与许可证）；不得改变「重建不是原件」的既有语义。

### R9 Windows 上的 Linux 运行时面（可选） —— v1.79.0+

- **目标**：Windows 用户可以把笔记本执行落到该平台自带的 Linux 子系统，而不是只能走托管运行时。
- **对标做法（证据）**：随包带安装指引文档，并有启停/重置脚本与相关测试，定位为「显式启用的预览能力」。
- **我方现状与差距**：全仓**无任何相关实现**（`grep -rn "wsl" src` 零命中），Windows 侧只有托管运行时与 powershell 路径（`src/main/windows*.ts`、`src/main/notebook/runtime-*`）。
- **差异化**：① 与预置离线环境一致的**探测—依赖矩阵—可执行指引**（未安装时给步骤而不是静默失败）；② 走子系统时把「解释器来自哪个发行版」写进环境证据；③ 明确标注为预览能力与其不可用边界（对标也是预览，但我们要把边界写进证据而不是只写文案）。
- **验收（真机断言，需 Windows 机器）**：① 未装子系统时给出可执行指引且不阻塞其他运行时；② 装好后能跑通一次分析并产出产物，环境证据含发行版信息；③ 卸载/重置后应用不再依赖它。
- **风险/依赖**：需要 Windows 机器与真机时间；**本机（macOS）无法验收**，因此排到最后且标记为可选。

## 7.3 「看起来强、其实弱」的可超车点（本轮新发现）

1. **它的「AI 表格抽取」还不是产品能力**：随包那个本地模型脚本自述是「离线实验，不是生产抽取器」（原文如此），生产路径是规则/几何启发式。→ 我们不背大权重，用规则 + 候选 + 审计就能正面超过。
2. **假阳性知识被写死在代码里（目录页 / 补充材料清单 / 机构署名）**：判定「不是表」的依据用户看不到。→ 我们把这些理由做成可读、可核对的界面项（同 R4）。
3. **保护能力是一串错误消息，不是矩阵**：平台能力缺失时的文案是「沙箱服务不可用」「组件缺失请重装」「网关端口不可用」「需要管理员设置」；远程命令的审批文案自述「不在沙箱中」。→ 我们把保护级别做成可查询字段 + 默认拒绝无保护远程执行（R1）。
4. **环境包只支持版本绑定的完整包**：通用活体环境导出、外部锁文件导入明确未做。→ 我们已有从锁离线重建，补「外部锁导入」即可超车（可直接并入既有模型/环境片，不必新开片）。
5. **确定性整会话重放未实现、环境证据不是求解器锁**（其自述）：这一条我们已经更严（重建代码永不等于复现、`not-comparable` 是一等结果）；要补的是它已经有的那部分——**会话级批量重放 + 可导出的验证记录**（小片，可并入 v1.78.0）。
6. **期刊属性「只保存选中项、空值不覆盖」是优点，但属性来源不可见**：用户不知道这个值从哪来、什么时候来的。→ 加来源/时间/方法与提交收据（R2）。
7. **容量上限只在超限时出现**：它把容量做成了 E2E 门与「已达容量上限」提示，但上限本身不是可读预算。→ 我们把「上限可见 + 可导出」当红线（并入 R6 的空间报告与既有存储/会话告警面）。
8. **批量安装退出应用即停**（第一轮已发现，此处复核成立）：我们做成可续队列（第一轮 K1a/K3 已排）。
9. **市场评分是发布方自评**（第一轮已发现）：我们展示本地可复算的触发质量分（第一轮 K2 已排）。

## 7.4 排序理由（层面二）

1. **R1 排最前**：它是**红线级**的小片——只做「保护级别的观测/展示/留痕/默认拒绝」，不新增原生依赖，却能同时改善笔记本、终端、后台与远程四个执行面的可信度；对标的弱点是「按平台报错 + 远程无保护」，这里最容易被我们做成可审计字段。
2. **R2 第二**：数据模型与界面都缺一整块（期刊实体与属性），成本低、用户可见度高，且顺带把「元数据改动有收据」这条可审计性立起来；与在飞的筛选计划共域，排在其后避免同表并行迁移。
3. **R6 与 R3 并列中段**：两者都是**中间层收益**——R6 对 8 GB 机器的空间收益是直接的（且需要先做存储层调查，越早查越好）；R3 把「未捕获」变成一等状态，是既有产物证据的自然补齐。
4. **R4 重但必须做**：真实论文表格是对标最「沉在底下」的资产，也是我们唯一还在单层启发式的解析面；但它是本层面最重的片，因此放在 v1.78.0 并强制与 R5 配对（先有语料再谈恢复层级）。
5. **R5 必须在 R4 之后**：没有语料的恢复规则只会越改越脆；把「退化即阻断」接进发布门槛，才让 R4 的复杂度可控。
6. **R7/R8/R9 更晚**：R7 依赖系统凭据设施与 R1 的展示面；R8 是随包资产（体积 + 许可证）；R9 需要 Windows 真机，本机无法验收，只能最后且可选。

## 7.5 明确不做（层面二）

- 不引入 OS 级沙箱原生组件进主包（R1 只做级别的观测与留痕；真隔离另立片并单独评估）。
- 不搬用任何具名文档/数据集/评测样本进仓库；抽取语料自造或使用可再分发样本（R5）。
- 不承诺期刊属性的覆盖率（属性获取是内容供给，不是代码量）。
- 不新增第三方大权重（对标那条本地模型路径自述只是实验，我们不追随）。
- 本任务不改产品代码/CHANGELOG/README/`.github`，不 commit/push，不新增依赖。

## 7.6 诚实边界（层面二）

- 本层面的对标事实全部来自**随包资产与数据模型的静态盘点**（资源目录、清单、内置资源清单、库资产、数据模型字段、发布/验收脚本），**没有运行对标应用做交互实验**。
- 因此「它是否把这些能力暴露到界面」在若干处只能由资源与数据模型反推（例如期刊属性的具体字段集、抽取恢复规则的可用入口、保护级别的用户可见性），这些一律在片内写成**要做的验收**而不是已成立的事实。
- `file:line` 均为本次实测行号；其中 `storageKey` 是否已构成内容去重（R6）**未确认**，因此 R6 的第一步被写成「调查」而非「重写」。
