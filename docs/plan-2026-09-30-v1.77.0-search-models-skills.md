## 1. 差异化红线（本批交付判据，逐条可在真机核验）

1. **「没找到」必须能自证是「没有」还是「没覆盖」**：检索与本地解析两侧同一条规矩——覆盖率、陈旧度、被截断的预算都要能在界面上读到，且写进响应证据。
2. **未验证内容绝不展示**：目录/制品校验失败时**具名失败 + 一条都不显示**，绝不静默降级成「展示未验证条目」。
3. **每个功能级模型必须写出回落路径且回落可查**：模型不可用/结果不明确 → 走确定性默认；该次回落要留痕（可查、可导出）。
4. **卸载本地资产不得删除派生结果**：删权重后派生结果仍可读；重装必须能命中本地缓存或给出明确下载量，不得重复下载。
5. **批量操作可停、可续、可回滚**：任何半装状态都必须可恢复；应用退出后重启要能说清上次队列停在哪。
6. **市场安装零执行**：安装期不执行来自包的脚本/可执行文件，且安装前显示将写入的路径清单（比对标产品「不运行包内脚本」更严：把清单也摊开）。
7. **本地可用性优先**：等价能力一旦落到本地（检索索引、解析模型），**断网可用**是验收项，不是加分项。

## 3. 逐片详情

### S1 检索作用域条与文件域分域 —— v1.77.0

- **目标**：命令面板顶部给出一排作用域芯片（全部 / 消息 / 会话 / 项目 / 上传文件 / 生成文件 / 文献库 / 标注），每个芯片显示**本类命中计数**；文件域一分为二，并在芯片区域写明「上传文件＝名称+已索引正文；生成文件＝仅名称；未索引不计入」。
- **我方现状与差距**：
  - 作用域枚举只有 `sessions | messages | files | literature | annotations`，无上传/生成之分：`src/shared/global-search.ts:26-33`。
  - 契约与数据面其实已够用：请求已带 `role/extensions/referenceTypes/since/until/cursor`（`src/shared/global-search.ts:52-72`），响应已带 **per-scope counts + scan 报告 + notes**（`src/shared/global-search.ts:244-256`），文件读取已按来源分流（`src/main/search/file-text-reader.ts:1-48`，`source: 'artifact' | 'upload'`），文件域命中退化为名称/路径时已会加 note（`src/main/search/global-search-service.ts:262-302`）。
  - 缺的是**界面**：当前只有 3 个下拉筛选，没有作用域芯片（`src/renderer/src/components/global-search/GlobalSearchDialog.tsx:1077-1160`），而且文件域只有一个 scope（`global-search-service.ts:262` 单口 `listFiles`）。
  - 界面文案侧已有「文件仅按名称匹配」的诚实提示键：`src/renderer/src/i18n/en.ts:2822`（`gs.contentFilesNameOnly`）。
- **差异化点（必须优于对标）**：对标只给一行静态说明；我们给**逐类实时索引实情**——每个芯片在计数旁显示该类本次扫描覆盖的上限/是否被截断（复用 `scan` 与 `notes`），点开能读到「为什么这条命中」（复用现有证据行：query/terms/snippet/指纹，`GlobalSearchDialog.tsx:807-925`）。即：**对标告诉你范围，我们告诉你覆盖**。
- **验收（真机断言）**：在打包/开发版应用里，对同一关键词：① 切换每个芯片，芯片计数与列表条目数一致；② 「上传文件」组能命中上传文档正文中的词，「生成文件」组对同一正文词**不命中**且界面明确写出不是「没有」而是「未索引/仅名称」；③ 当会话/文件预算被打满时，界面出现被截断提示且提示里的数字等于响应 `scan` 的数字；④ 点任一命中能展开证据行并显示指纹。
- **风险/依赖**：作用域枚举扩项会牵动 `resolveSearchScopes`、pin 描述串与既有测试面：`src/shared/global-search.test.ts`、`src/shared/global-search-paging.test.ts`、`src/main/search/global-search-service.test.ts`、`src/renderer/src/components/global-search/GlobalSearchDialog.test.tsx`、`e2e/certification/palette-commands.spec.ts`——迁移要**向后兼容**（旧 pin 的 scope 串仍可解析、仍可验证）。无外部依赖。

### S2 检索高级筛选面板与可自证筛选集 —— v1.77.0

- **目标**：一个「高级筛选」入口收纳：作用域、项目/集合、时间窗（不限/最近 7 天/自定义）、发送者、格式、文献类型、**结果排序**（相关度 / 时间）；筛选集可保存、命名、复用，并能在结果摘要行上**自证**。
- **我方现状与差距**：请求契约已支持时间窗与多类过滤（`src/shared/global-search.ts:52-72`），但界面**完全没有时间窗与排序控件**（`GlobalSearchDialog.tsx:1077-1160` 只有 3 个 select，`grep` 全文件无 `since/until`）。已有的「保存的筛选集」是 pins（`src/shared/global-search-pins.ts:150-176`，`GlobalSearchDialog.tsx:1166-1250`），且已有机器稳定描述串 `describeGlobalSearchFilters`（`global-search-pins.ts:160-176`）——**这是对标产品没有的东西**。
- **差异化点**：对标有「结果排序」但筛选集是**匿名状态**；我们把筛选集做成**可命名、可复现、可自证**的实体：应用一个 pin 后，摘要行给出该 pin 的机器可读描述（scopes/project/since/until/role/extensions/referenceTypes），并且结果里的证据行仍可**验证命中**（块指纹未变才算通过）。即：**对标能筛，我们能证明这批结果是在什么条件下得到的**。
- **验收（真机断言）**：① 设「最近 7 天 + 仅我发送 + 只表格格式」后，列表条数小于不限时间的结果，且摘要行出现的条件串与界面上的选择逐项对应；② 保存为 pin 后重开面板应用，结果与保存时一致；③ 把某条命中所在会话改动后再点「验证」，出现「证据已变化/未找到」而非静默通过；④ 清空筛选后结果集回到初始条数。
- **风险/依赖**：与 S1 共用同一面板与 i18n（9 种语言字典需同步；**本任务不碰正在被并发编辑的字典文件**，实现时统一改）。无外部依赖。

### M1 模型用途分域 + 功能级模型位 + 真检测 + 回落留痕 —— v1.77.0

- **目标**：设置→模型页按**用途**分区：当前模型（对话）、**功能模型**（能力自动选择、文献归类等）、**本地解析模型**（壳，内容由 M2 填）。每个功能行必须展示：实际生效的模型、**回落路径**、以及一次**真实检测**（有耗时与用量，不是只有通过/失败）。
- **我方现状与差距**：
  - 我们只有「场景模型」三个：`session-detail | subagent | review`（`src/shared/settings.ts:344-350`），UI 在 `src/renderer/src/pages/settings/ProvidersPanel.tsx:362-379`；另有视觉模型中继 `ProvidersPanel.tsx:384-393` 与每场景推理强度（`ScenarioModelSelect.tsx:35-80`）。
  - **没有**「功能级模型」这一层：全仓 `grep -rn "classif" src` 的命中都是无关语义——错误分类（如 `src/main/settings/validate.ts:259` `classifyStatus`、`:269` `classifyFetchError`）与连接器描述符措辞——没有任何「为某个功能选一个模型」的概念。
  - 模型服务的 CRUD/连通性测试已存在（`ProvidersPanel.tsx:120-345`，`ProviderForm.tsx`），可以复用成「功能模型」的选择器与检测按钮。
- **差异化点（必须优于对标）**：对标只说「首个服务会自动用于这两项功能」+ 一句隐私边界；我们做到**可审计**：① 每个功能行显示「本功能当前使用 X（来自服务 Y）；不可用时回落到内置确定性策略 Z」；② 检测按钮跑一次**真实往返**并显示实际耗时与用量（对应我们的 token 用量设施）；③ 每次回落写入一条可查事件（会话/设置里能翻到「这次归类为什么没用模型」）。即：**对标告诉你用了哪个模型，我们告诉你为什么、花了多少、失败时走了哪条路**。
- **验收（真机断言）**：① 不配任何功能模型时，功能仍工作，且事件区能查到「按默认方式执行」；② 给功能模型指一个不存在的模型名，点检测 → 界面**具名失败**且不改变功能行为；③ 用可用模型检测 → 显示通过 + 真实耗时（>0 且与实际等待相称）；④ 检测通过后触发一次真实归类/能力选择，事件区出现「用模型 X 完成，未回落」；⑤ 运行中断网触发一次 → 事件区出现「模型不可达，回落默认方式」，功能结果仍然产出。
- **风险/依赖**：功能模型若与主对话共用同一服务与密钥（对标产品如此），必须在 UI 说清**共用**还是**独立**，避免用户以为换了密钥；密钥删除策略沿用现有「移除服务会恢复默认」的既有语义。

- **风险/依赖**：无外部依赖；i18n 9 语言同步（不碰并发编辑中的字典文件）。

- **差异化点**：① **校验不通过就一条都不显示**，并具名失败（对标产品也是这个取向，但我们把失败原因分型并给「如何修复来源」的路径）；② 安装前除预览与冲突选择外，额外展示**将写入的路径清单**与**将被替换的文件**；③ 安装队列做成**可续**：应用退出后重启能说清上次停在哪、失败项可单独重试（对标产品明说「退出应用将停止队列」，这正是我们要超过的点）。
- **验收（真机断言）**：① 目录源可达时列表出现计数（`结果: x / y` 形状），分类筛选可切换；② 手工把源签名改坏后刷新 → 列表**为空**且显示具名校验失败，不出现任何未验证条目；③ 安装一个技能：安装后技能在已安装列表与技能目录出现、可用性矩阵可见、会话里能被触发；④ 安装一个与本地已有技能同名者，出现逐项冲突选择，选择「保留本地」后本地文件**字节未变**（比对摘要），选择「覆盖」后可回退；⑤ 安装进行中关闭设置 → 队列继续；退出应用再启动 → 能读到上次队列状态并可继续/重试。
- **风险/依赖（关键）**：**硬依赖「官方技能目录已发布」**。若发版前目录未就绪：本片**降级**为「协议扩展 + 只读目录壳（空目录 + 明确的未配置态）」，其余片不受影响；目录内容供给放在 K3，属发布/运维工作而非代码，**排期不得把内容量当代码量来承诺**。

### M2 本地解析模型资产管理 —— v1.78.0（若 K1a 被源阻塞可提前到 v1.77.0）

- **目标**：设置里出现「本地解析模型」页：列出可选的本地能力（来源、语义版本、安装后大小、当前生效版本），可下载/校验/卸载；**卸载保留派生结果**；落地后**断网可用**。
- **我方现状与差距**：
  - 已有**校验式下载原语**：`src/main/engines/model-weight-cache.ts:1-60`（无发布方 sha256 即**拒绝**下载、使用前**重哈希**、缓存目录按 modelId 分桶、返回 `needs-consent / unresolved / checksum-mismatch / cached / downloaded` 分型）——但它**没有任何生产调用方**（`grep` 非测试引用 = 0），是「有原语无功能」的典型差距。
  - 本地 PDF 解析目前只有 pdfjs 的逐页文本/书签/图片对象检测：`src/main/settings/pdf-service.ts:1-6, 366-460`；没有模型资产目录、没有版本指针、没有下载面。
  - 检索侧同样受「无后台索引」约束：`src/main/search/global-search-service.ts:27-30`。
- **差异化点（必须优于对标）**：① **无校验即拒绝**写进产品语义（对标有「校验失败重试」，我们有「没有发布方校验值就根本不下」）；② 权重与派生结果**解耦**：删权重不删结果，且重装时优先**缓存命中**（界面明示「本次为 0 下载」或给出准确下载量）；③ **离线可用**为验收项：下载完成后断网，解析与浏览仍工作；④ 每个派生结果带 `模型 revision + 输入指纹`，可回答「这份结果由哪版模型、哪个输入产生」。
- **验收（真机断言）**：① 未同意前不发起任何下载（抓网络确认 0 字节）；同意后下载完成，`active` 指针指向新版本，界面显示安装后大小与实际目录 `du` 一致；② 把权重文件改 1 字节 → 使用该能力时**具名报错且不使用**，不静默复用；③ 卸载权重 → 已有派生结果仍可打开浏览；④ 重装 → 命中本地缓存（界面显示 0 下载或明确增量）；⑤ **断网**后重复一次解析与浏览，全部成功。
- **风险/依赖**：权重体积可能达数百 MB 级（对标产品该项 234.5 MiB，本机实测磁盘 235M），**8 GB 机器**（本机环境）下载与解压必须串行、可取消、可续；本地推理运行时（WASM/ONNX）是新增产物 —— **本片只做资产管理，不做推理**（推理在 M3）；不得新增依赖进主包，运行时按需拉取并校验。

### S3 增量全文索引 + 覆盖率诚实报告 —— v1.78.0

- **目标**：把「不做后台索引」变成**可增量、可续、可读覆盖率**的索引；任何「没找到」都能显示该内容是否在覆盖范围内、索引是否陈旧。
- **我方现状与差距**：当前行为被写死在注释里：扫描显式有界、无后台索引（`src/main/search/global-search-service.ts:27-30`）；会话 400、标注 500、文件正文 40 个（`src/shared/global-search.ts:20-22,50`；`src/main/search/handlers.ts:67,71`）；文件域命中退化时已会加 note（`global-search-service.ts:301-302`，文案 `src/renderer/src/i18n/en.ts:2822`）。这已经比对标产品诚实（它需要重启才启用全文检索），但**覆盖面小**。
- **差异化点**：对标产品把全文索引做成**启动期就绪**（用户要重启），我们把索引做成**在线增量 + 进度可读 + 陈旧度可读**：索引进行中搜索会返回「本次未覆盖 x 个文件」而不是静默少命中；索引崩溃能续（checkpoint）；索引完成后同一查询条数单调不减（真机可验）。
- **验收（真机断言）**：① 新导入一批文档后立即搜索 → 出现「未覆盖」提示与数量；索引完成后同一查询条数增加；② 索引进行中关闭应用再启动 → 不从头重建（可观测的已处理计数不回退）；③ 删掉索引目录后搜索 → 提示覆盖为空而不是「没有结果」；④ 对同一查询，索引前后命中集合是**超集关系**（不存在索引后反而少命中）。
- **风险/依赖**：这是本批**最重**的一片（迁移 + 后台预算 + 存储占用），必须给后台预算与存储上限，且不得拖慢启动；与 S1/S2 的界面契约向前兼容。

- **目标**：在 K1a 之上补齐：分类与安装状态筛选、名称/目录顺序排序、`结果: x / y` 计数分页、**可停可续可重试**的批量安装、更新提示与「安装前预览」的完整诊断。

### M3 图注/表格候选解析与浏览 —— v1.79.0+

- **目标**：本地解析模型产出「图/图注/可复制表格候选」，可在阅读器里浏览并复制，候选带页码与置信信息。

## 4. 排序理由（为什么这样切）

1. **先补「可见性」而不是「新能力」**：S1/S2/K2 都是**已有数据面 + 缺界面**（counts/scan 已在响应里、评分器已在、筛选契约已在），单版内可做完且真机可验；对标产品在这三处只是「有」，我们能做到「有且能自证」。
2. **M1 先于 M2/M3**：分域是**概念与信息架构**，成本低、可立刻消除「三个模型页」这一最显眼差距；而本地解析模型是重活（下载/校验/运行时），把它排在 M1 之后，避免 v1.77.0 被一个 235 MB 级产物拖住。
3. **K1a 排队首但带硬依赖**：市场是三项里最大的**内容+机制**缺口，机制我们可以复用现有专家市场的签名/sha256/批量安装设施，**内容**依赖官方目录发布；因此先做「只读纵切 + 单条安装」，并在片内写明降级路径，不让目录未就绪变成发版阻塞。
4. **S3 放 v1.78.0**：索引是唯一会动存储与启动路径的重活，它必须在 S1/S2 的界面契约稳定之后做，否则会返工两次。
5. **M3 放更晚**：收益高但成本/风险同样高（新增运行时、大权重、内存受限），且它依赖 M2 的资产面先稳定。

## 5. 明确不做 / 不作承诺

- 不承诺技能目录**条数**（内容供给是发布工作，不是代码量）；不把「对标有 525 条」当作我们的验收指标。
- 不照搬任何对标文案与命名（作用域、分类、筛选label 用我们既有术语体系）。
- 不做「安装期执行包内脚本」这种便利（红线 6）。
- 不在本批引入任何新运行时依赖进主包；本地推理运行时按需下载并校验。
- 本任务不改产品代码/CHANGELOG/README，不 commit/push。
