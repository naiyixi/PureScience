# 基金申请书结构审计

## 目标

不评价"写得好不好"，只回答结构性问题：**缺口是否成立、问题是否可检验、内容是否可交付、创新是否相对某物**。逐条给出证据位置（第几节第几段），不给泛泛建议。

## 审计清单（按顺序，前一项不成立就不必看后一项）

### 1. 立项依据：缺口句

- 有没有一句**可引用的缺口陈述**："X 已被证明（引文），但 Y 在 Z 条件下仍不清楚（引文），因此无法 W"？
- 缺口是**知识缺口**还是**资源缺口**？只有"我们缺少设备/平台"不构成科学缺口。
- 引文是否支撑缺口本身，而不只是支撑背景？逐条标注：背景引用 / 缺口引用 / 方法引用。

### 2. 科学问题：一句话可检验

- 能否写成"在 <人群/体系> 中，<干预/因素> 是否通过 <机制> 影响 <可测量结局>"？
- 若只能写成"研究 X 的机制与应用"，说明问题未收敛。
- 假说是否**可被证伪**？写出"什么结果会推翻它"。

### 3. 研究内容：动词 + 对象 + 可交付

- 每条内容应是"做什么 + 得到什么"，而不是"用什么方法"。
- 内容条数通常 3–4 条；超过 4 条往往是**方法被误写成内容**。
- 每条内容能否对应到后面"技术路线"的一支？对不上就是悬空内容。

### 4. 研究方案与技术路线

- 是否有**路线图**，且每个节点对应一条内容与一个产出？
- 关键技术难点是否被点名，并给出**备选方案**（评审最常问"做不出来怎么办"）。
- 样本量/例数是否有依据（交给 sample-size-power 复核）。

### 5. 创新点：相对谁

- 每条创新点必须能补全句式"相对 <已有工作>，本申请首次/不同地 <做了什么>"。
- "首次将 A 用于 B"要核实是否真无先例；"系统性/全面性"不是创新点。
- 创新点条数 2–3 条为宜；与内容重复的条目应删。

### 6. 研究基础与可行性

- 有没有**预实验数据**（图/表/初步结果），而不是只有"我们团队长期从事…"？
- 团队分工是否与研究内容一一对应？
- 平台条件是否写到具体设备/样本库/队列，而不是"具备良好条件"？

### 7. 格式与合规

- 对照当年指南逐条核：申报类别、限项、预算科目与上限、伦理与生物安全、动物实验许可、合作单位盖章。
- 篇幅是否超限（含图表）、参考文献格式是否统一。

## 产出

- **缺口清单表**：章节 / 问题 / 证据位置（原文片段）/ 严重度（阻断 / 扣分 / 建议）/ 修改方向。
- **一句话诊断**：这份申请最可能被拒的理由是什么。
- 不改写全文；只指出位置与方向，改写由作者完成（避免审计者替作者编数据）。

## 常见失败（逐条自检）

- [ ] 把"研究内容"写成实验步骤清单。
- [ ] 创新点写"首次系统研究"，无法指向任何已有工作。
- [ ] 科学问题里同时含三个自变量与五个结局（不可检验）。
- [ ] 技术路线图与内容条数不一致。
- [ ] 预算与研究内容规模不匹配（大预算小内容 / 小预算大内容）。
- [ ] 引用近三年文献比例过低，或全部自引。
- [ ] 审计意见写成"建议加强创新性"这类无法执行的句子。
