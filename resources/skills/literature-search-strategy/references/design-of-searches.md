# 系统评价级检索设计（灵敏度优先）

> 适用：循证证据综合、临床指南、监管证据包等"漏检即结论失真"的场景。
> 目标不是"搜到一些文献"，而是**可复现地逼近全量**并让读者能审计检索的完整性。

## 检索结构：四层

1. **数据库检索**：主题词 + 自由词双轨（每库独立映射）。
2. **引用回溯**：对最终纳入文献做 backward（扫其参考文献）与 forward（谁引用了它）追溯。
3. **补充检索**：临床试验注册库（如临床试验注册平台）、预印本、会议摘要、灰色文献（视主题）。
4. **专家咨询/人工补漏**：可选；未做时如实说明。

## 概念拆解原则

- 每个 PICO/PECO 要素独立成组；人群概念若过于宽泛（如"患者"）可不作限定，靠干预/暴露组收窄。
- 结果（O）通常不进检索式（结局表述多样，会漏检），改为纳入筛选阶段判断。
- 研究类型过滤器放在**检索后**或作为独立行，先用纯概念式跑一遍对比敏感度。

## 灵敏度-精确度权衡

- 系统评价默认**高灵敏度**：宁多勿漏，靠题目/摘要筛选去噪。
- 只有当命中数大到不可管理（如 >1 万）时，才与用户确认是否收紧；任何收紧都要记录对灵敏度的预期损失。
- 中文场景常见陷阱：只用英文库（漏中文研究）；只在 CNKI（漏学位论文/会议）；不同中文库收录重叠高但并非包含关系。

## 检索式开发流程

1. 找 2-4 篇**金标准文献**（用户提供或从主题综述的参考文献中识别，需用户确认）。
2. 把金标准文献的关键词逐一映射进概念组，迭代检索式直到金标准全部命中（召回自检）。
3. 多库执行后合并去重（题录去重按 DOI/PMID/标题归一化，中文文献按标题+作者+年份）。
4. 记录每步命中数与排除理由，形成 PRISMA 流程图数据。

## 记录与报告（对齐 PRISMA-S 要素）

如实记录：每库名称与检索日期、完整检索式（含平台）、是否用了过滤器及其理由、检索人员、去重方法。任何一项缺失都应在报告中标注为"检索可复现性缺口"，不得隐去。

## 红线

- 不编造命中数量、数据库名称之外的库、检索日期。
- 用户未指定时间范围时，不默认"近 5 年"等裁剪——除非用户明确要"最新进展"并理解灵敏度损失。
- 不做"搜了 X 篇所以结论可靠"的断言：检索完整性只是证据综合的一个环节。
